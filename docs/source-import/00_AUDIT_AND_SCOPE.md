# 外部信源导入对齐：检查结论与交付范围

版本：DeepAha 3.0.0-rc2。日期：2026-09-17。上一基线是本会话交付的3.0.0-rc1压缩包，不是本机未上传代码或最新远程主线。

## 一、实际核查的输入

1. `DeepAha_Rebuild_3.0.0-rc1.zip`：本轮从交付文件解压独立开发。
2. `DeepAha_Source_Asset_Importer_v0.3.1.zip`：实际从个人资料库取得的上传版本。未修改该工具源码，完整随包附于 `tools/source_asset_importer/`。
3. `WB-scout.zip`：实际取得的研究原件；只作离线、临时库格式回放，没有批准其中任何正式来源。
4. 本项目WMA结果整体审核规划，以及v2.2外部Scout人工交接边界。

无法取得 `DeepAha_Research_99762cfa35a48bfe_r58.zip` 的原始字节，因此本轮不能声称验证过该具体文件。替代的是：用实际v0.3.1源码，从实际WB-scout原件重新导出一份研究包，再经新系统接收并将反馈交回原工具。各输入的SHA-256见 `INPUTS_AND_REUSE.json`。

## 二、rc1缺了什么

`backend/src/deepaha/product/sources.py::import_sources` 仅接受简化来源JSON，并逐条调用正式来源登记。它没有v0.3.1研究ZIP清单、原件还原、候选暂存、历史观察、完整Brief映射或主系统反馈接口。原界面只能选择JSON，不能把“已有一个来源导入函数”当作工具已经对齐。

工具的当前主路径是“离线工作台 → 导出研究交接包”，输出 `deepaha.research-handoff.v1`。其中PROPOSE_STAGING仅是外部建议，既不是DeepAha来源批准，也不是WMA任务。沿用原来的简化接口会丢信息或错误提高其权限。

## 三、这次修改与保留

| 部分 | 实施结果 |
|---|---|
| 工具与文件 | v0.3.1工具原样保留；支持其真实导出、v2.2 Handoff及GPT/WB原研究ZIP |
| 主系统接口 | 独立来源资产接收端点，使用当前登录、操作员权限、CSRF和事务，不新建账号系统 |
| 原件与投影 | 先保存上传原件；外层清单重验；从originals重建，不信任客户端审核结论 |
| 候选与研究历史 | 研究分组、稳定候选、批次观察、Brief、依据、关联和原始State均保留；State不重复计为新候选 |
| 正式来源 | 复用Source/SourceProfile；只有一次明确来源批准才登记或关联，不因接收研究包自动建源 |
| WMA接入 | 创建任务时冻结选用Brief与来源政策；由现有Direct WMA Worker读取；导入和批准均不自动派发 |
| 反馈闭环 | 系统接收回执 + scout-feedback.v1，按持久事件回读；原工具实际能读回 |
| 运行维护 | rc1→rc2显式加表，SQLite升级先备份校验；NGINX专用上传入口和Node代理超时同步对齐 |
| 旧路线 | 不复活旧Provider、方法认证、逐字段审核、Native Automation Worker或内部开放扩源 |

## 四、不改变的边界

本轮完成的是文件提交、候选保存、明确来源批准、任务资料衔接和反馈回读。它不是来源真实性审计、采集效果评测、真实WMA调用、支付、商用上线或资料库自动连接项目。

来源图谱、需求研究和维护提案按研究记录完整保存，但不自动执行提案中的MERGE/RETIRE，不把“研究者声称失效”写成来源正式停用，不增加通用图谱平台。

`tools/source_asset_importer` 的资料库/Codex功能没有取消，但仍依赖用户机器、连接及既有权限；本轮没有验证其真实私有资料库连接。手工下载、导出和上传始终可用。归档到ChatGPT资料库不等于导入DeepAha数据库。
