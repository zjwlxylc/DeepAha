# SG5.1 人工验收说明

版本：`3.5.1-rc1`

SG5.1 不是 SG6。它只验收两个问题：

1. WMA 已经读到的时间，能否在**作用域 + Evidence + 安全规范化**之后真正用于报名截止、提醒和 `Why now`；
2. `/review/catalog` 能否从“数百条具体机会平铺”改成一个适合运营管理的“父公告 → 具体机会”工作台。

## A. 时间语义验收

打开机会总览与具体机会详情，重点看三类情况：

### A1. 时间已明确

应显示官方材料支持的报名截止。例如用户上传的数据副本中：

- 浙江省属事业单位招聘：`2026-08-19 16:00`；
- 中国邮政河北省分公司校招：`2026-10-31`；
- 黑龙江烟草招聘：`2026-06-18`。

这些 Target 才允许：

- 设置截止提醒；
- 进入日历；
- SG5 `Why now` 计算“还剩 N 天 / 已截止”。

### A2. 时间待确认

如果日期存在但 Evidence 未定位、作用域不清或存在冲突，应显示：

- `关键截止待确认`；
- `时间冲突`；
- `时间更新待收录`。

此时**不能**生成精确倒计时和提醒。

### A3. 滚动受理

明确写“全年滚动受理 / 招满即止”等并有 Evidence 时，显示：

> 滚动受理

不能伪造成某一天截止。

## B. 收录管理验收

访问：

`http://127.0.0.1:8000/review/catalog`

默认应进入 **按公告** 视图。

### B1. 顶部运营摘要

至少包含：

- 当前具体机会；
- 父公告 / 根机会；
- 更新待处理；
- 时间待确认；
- 已过截止。

这些数字可以点击进入对应筛选。

### B2. 父公告分组

每个父公告只占一个管理卡片，并显示：

- 机会类别；
- 具体机会数量；
- 收录状态分布；
- 时间质量分布；
- 最早安全截止；
- 最近更新时间；
- 若干代表性具体机会。

按用户上传快照，预期约为 **6 个父公告、328 个当前具体机会**，而不是 328 行重复父公告。

### B3. 展开具体机会

点击“展开具体机会”，应能看到该父公告下的岗位 / 赛道 / 政策分项；仍然可以**只撤回一个具体机会**。

### B4. 按具体机会

切换“按具体机会”，保留精确搜索、筛选和单 Target 撤回能力。SG5.1 不增加父公告默认一键撤回。

## 人工验收停止线

SG5.1 只有在以下两点都符合直觉后才算通过：

- 用户端不再普遍显示“时间节点尚未明确”，但不安全日期仍然保持不确定；
- 审核/收录管理从“浏览重复大表”变成“先看公告健康，再进入具体机会处理”。

人工验收通过之前，不进入 SG6。
