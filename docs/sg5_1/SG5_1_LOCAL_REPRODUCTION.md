# DeepAha SG5.1 Windows 本地复现

## 1. 使用已有数据

继续使用你当前的数据目录：

```text
C:\Users\LENOVO\deepaha-data
```

不要删除 `deepaha.db`，不要移动 `objects`，也不要重新调用 WMA 来验证 SG5.1。

## 2. 启动

1. 停止旧版 DeepAha；
2. 将 `DeepAha_Rebuild_3.5.1-rc1_SG5_1.zip` 解压到**新的程序目录**；
3. 保留原数据目录；
4. 双击根目录 `启动机会星图.cmd`。

启动器第一次发现尚未完成 SG5.1 时间投影时，会执行：

```text
upgrade
→ upgrade-sg1
→ upgrade-sg5-1
```

`upgrade-sg5-1` 会先在 `deepaha-data\backups` 创建并校验备份，然后只读取已经保存的 WMA 原件重新生成 milestone 投影。

它不会：

- 重新调用 WMA；
- 改写 `objects`；
- 新建数据库 Schema；
- 修改旧审核决定。

第二次启动应直接报告当前版本已完成，不重复改数据。

## 3. 先检查收录管理

访问：

```text
http://127.0.0.1:8000/review/catalog
```

确认默认是 **按公告**。

按你上一轮上传给我的快照，升级副本得到：

```text
328 个当前具体机会
6 个父公告 / 根机会
282 个安全报名截止
46 个时间待确认
68 个当前 OPEN
214 个已经 CLOSED
```

如果你本地后来又新增了 WMA 数据，数字会随真实数据库变化，这是正常的。

重点检查：

- 中国移动杯竞赛：21 个赛道聚合成 1 张父公告卡；
- 浙江多家事业单位：26 个岗位聚合；
- 宁波一次性求职补贴：7 个政策分项聚合；
- 中国邮政河北：68 个岗位聚合；
- 浙江省属事业单位：106 个岗位聚合；
- 黑龙江烟草：100 个岗位聚合。

展开任一父公告，应能进入具体机会表；撤回按钮仍然写“撤回具体机会”。

## 4. 检查时间

打开机会总览：

```text
http://127.0.0.1:8000/app/overview
```

在“时间已明确”的机会中，应直接显示安全报名时间；在 Evidence 不足的机会中继续显示“关键截止待确认”。

打开具体机会详情：

- READY：允许设置提醒/加入日历；
- PARTIAL / CONFLICT / PENDING_UPDATE：提醒按钮不可用；
- ROLLING：显示“滚动受理”，无虚假倒计时。

然后进入“我的机会星图”。SG5 的 `为什么现在` 会自动使用 SG5.1 新形成的安全截止，只有安全 deadline 才会出现“还剩 N 天”。

## 5. 回退

首次 SG5.1 升级会生成：

```text
deepaha-data\backups\before-sg5-1-*.zip
```

需要回退时先停止程序，再按项目已有 `restore-backup` 流程恢复到新的测试目录核对，不要覆盖唯一生产副本后再验证。

## 6. 验收边界

本地人工验收重点是产品组织与真实视觉体验。当前云端执行环境的原生 Chromium 导航受管理员策略限制；交付包内保留了使用真实 FastAPI + 数据副本的显式 HTTP bridge 截图证据，但它不替代你的 Windows 浏览器验收。
