# Mobile R3 运行与升级

本包是你上传的 Mobile R2 完整系统加上已接入的订阅、荐源、定制跟踪与网站分享，不是 S1 独立演示包。旧 LOGO、三张首页海报、已存在的机会/画像/整体审核/Scout/Direct WMA 路线保留。运行入口仍为 `deepaha.main:app` 或原来的启动脚本。

## Windows 本地

使用 Python 3.13 或 3.14。完整系统沿用 R2 的版本要求，不是此前独立 S1 的 Python 3.11 要求。停止旧版后，将本包解压到新文件夹，双击根目录 `启动机会星图.cmd`。首次需要联网安装 `backend/requirements-product.txt`；这次新增 Pillow 并将 pypdf 兼容范围明确为 5.9 至 6.x。正式验收前应在目标机器按此要求安装；本轮并非 Windows 实机全新安装。

默认数据目录依然是 `%USERPROFILE%\deepaha-data`。原登录账号、来源、总览、原件都在数据目录里，不能删除、不能用包里的测试数据覆盖。环境变量 `DEEPAHA_DATA_DIR` 指定了其他目录时，以实际配置为准。压缩包不包含你的数据库、密钥或运行中的任务数据。

已有数据库：启动器先运行原来的兼容升级，再执行 `upgrade-services`。首次 R3 升级会验证备份后新增14张 `mbr_` 表；再次运行是只读版本检查。新安装：原来的账号设置流程会一次建立全部结构；不会创建示例收费订单或打开采集开关。

程序目录和前端版本会打印在启动窗口；本轮前端指纹以 `mobile-r3-` 开头。不要把新 JS 与旧 CSS 混合复制到旧目录。遇到资源校验不一致，在仓库根目录运行 `python scripts/services_r3/build_assets.py --check`；开发改动后运行同脚本不加 `--check` 更新整组指纹。

## 打开后先检查这些入口

| 使用者 | 入口 | 可以做什么 |
|---|---|---|
| 所有人 | `/services` | 查看已上架服务；未上架时显示真实空状态 |
| 用户 | `/app/subscription` | 当前权益、起止时间、申请、报价确认、后续服务期 |
| 用户 | `/app/tracking` | 主题跟踪、已批准网站跟踪、暂停/恢复、检查时间与错误 |
| 用户 | `/app/sources` | 免费推荐公开网站、查看审核结果、补充说明 |
| 审核员 | `/review/sources` | 通过/退回补充/拒绝网站线索，不等于发布机会 |
| 维护员 | `/manage/services` | 套餐、价格、服务项目、申请、权益、调查进度和记录 |
| 维护员 | `/manage/services/runtime` | 启用服务检查、是否允许外部调查、每轮上限及执行连接 |
| 维护员 | `/manage/sharing` | 分享域名、标题、描述、两种封面与微信配置状态 |
| 所有人 | `/share` | 可点击访问网站的公开分享落地页 |

普通用户可以在手机操作订阅和反馈。维护工作台继续沿用 R2 的手机只读策略：窄屏查看，电脑执行管理写操作。付费不增加审核/维护权限；维护员沿用 R2 对审核权限的继承关系。

## 第一次启用订阅

三档预置套餐默认草稿，不能直接视为已经在售。维护员在“订阅与服务”逐一审阅价格、期限、名额与服务项目，再确认上架。初始价格是产品试运营配置，未经过真实付费实验：基础29.90元/2个自然月，深度129元/12个自然月；定制按申请单报价，不虚构一个统一价格。

用户提交申请不会自动获得权益。维护员可以明确“赠送试用”，或者在独立真实收款后选择“人工核对开通”，填写金额、唯一核对凭据和原因。本包没有微信/支付宝自动收款、回调验签、自动续费和自动退款，不能把人工开通当成支付接口成功。

续购/换档从现有服务结束后接续。本轮不提供立即升级补差价。后台修改套餐不会追溯改变旧订单和已开通权益。需要终止权益可以撤销，但撤销不是退款完成；退款仍须在实际收款渠道处理。

## 第一次启用持续跟踪

已购买用户创建主题；定制用户可以对自己提交且审核通过的网站点击“加入我的网站跟踪”。定制申请表也支持同时填写一个公开网站，申请和荐源在同一事务内保存，错误不会留下半个申请。只有描述目标、没有填写网址时，正常形成待报价申请，后续可在网站建议补充。

网站进入来源审核后，审核员只做整体判断并写公开调查说明。维护员登记/复用原来源，再明确启用该来源。不会因为有人提供网址就擅自花费模型调用预算；用户画像与私人说明不进入 WMA 调查上下文。

最后到“运行设置”：先启用服务检查，选择原来已登记的执行连接；需要自动调查指定网站时，再明确开启“允许外部网站调查”。原 `deepaha.product.cli worker` 进程承担周期检查，不需要第二套账号、另一个 Web 服务或 ChatGPT 定时任务。本地启动器会启动此进程；服务器需确认对应 worker 正在运行。

服务运行检查每小时触发，按套餐间隔选出到期项目。默认主题目标间隔：基础24小时、深度6小时；外部网站调查默认24小时，最短24小时。每轮网站上限默认3。队列、来源、实际Worker可用性和模型耗时会影响实际完成时间，界面显示的“上次检查/失败”才是运行结果。没有真实 WMA 配置时，目录检查仍可进行，外部采集不能称为已验证。

采集结束先显示“结果待审核”；整体审核通过后才显示发布状态并生成具体机会链接通知。到期、停用、暂停或清理后，执行前再次核对授权，不再发出新调查。已在远端接受的调查可能已有费用，不能承诺本地取消消除这些费用。

## 个人数据处理

原导出包含新增申请、权益、网站提交、跟踪、调查进度和消息。清理在原数据库事务内删除私人提交文本、跟踪、相应消息和后续授权，取消尚未完成的本地任务，并清理相关重试缓存。必要的订单条款、权益、收款核对和审计记录保留且页面明确说明；账号本身保留，不自动退款。已获批准的公共来源及原正式事实不会因为某一个用户清理资料被删除。既有备份需要运营方按自己的数据保留流程管理。

## 常见状态

“服务方案正在准备中”：套餐仍是草稿。 “周期检查未启用”：维护员尚未授权运行，或从备份恢复后主动暂停。 “等待来源接入”：来源通过审核但未登记/授权。 “服务到期或已暂停”：不再继续安排检查。 “结果待审核”：原WMA返回候选，不代表机会发布。 “微信凭据尚未配置”：OG仍输出，但专用微信分享样式不启动。
