SECTION 01

DeepAha 订阅与用户来源补充｜S1 产品和技术设计

日期：2026-09-21。目标基线：DeepAha Mobile R2（mobile-r2-c8d459040dd2）。

交付范围与基线事实

用户授权本轮先研究设计、随后直接实施，不再逐阶段等待确认。资料库可读到 R2 回执与报告，但三份目标文件的原始字节导出均返回没有授权的 raw-byte materialization path；当前容器没有 R2 源码。GitHub main 的读取指向 edb01d247ec5069624b24682c89ac5660a68db6f，未找到 CHANGESET_MOBILE_R2.json。不能把 main 视为 R2，不能重造旧功能后声称完整升级。

本轮范围因此为可运行、可测试的新增业务模块、现有 Product 接口适配器、精确 R2 输入包的离线组装工具、完整设计/测试/接入说明。R2 整包联调、原首页导航接入、原有测试回归仍须取得基线后完成。本模块不是另起一套机会发布核心，不取代原系统。

第一性原理与取舍

机会是低频但高价值的需求。免费库的任务是让真实机会可见，不能通过隐瞒来源、降低准确性、取消基本收藏与原有截止提醒逼迫付费。收费对象是减少用户持续筛选、反复检查、跟踪特定来源的时间，而非承诺录取、获奖、符合资格或“包找到”。

比较了三条路径：只改套餐文案不能真正区分服务；把免费事实与依据锁起来违背产品价值；推荐“公开事实免费 + 有限额的持续跟踪 + 需先评估的定制履约”。不引入新大模型，不改变资格判定，不绕过原整体审核。

后台设置

维护员可新增/修改服务项目名称、描述、启用状态。自动能力仅有 topic_watch、site_watch、inapp_alerts；可新增标为 manual 的人工履约项目，不把后台文字当可执行代码。套餐可创建、发布新版本、上下架、改变显示名/周期/价格/包含服务/名额/检查间隔。旧版本保留；已下订单和已开通权益不被新价或下架追溯修改。

仅维护员（operator）可改价格、报价、人工确认开通、撤销权益、创建实际采集任务。维护员继承 reviewer。普通审核员只处理线索审核。服务角色和订阅等级分离；付费不增加审核或管理权。

订单、权益与时间

金额用人民币“分”整数，禁止浮点计价。订单需客户端幂等键和所见套餐版本；价格变化返回409，要求重新确认。不以用户点击“已付款”开通。

首版无真实支付通道。订单为待服务确认；维护员只能以“试用赠送”或“已人工核对外部付款”方式开通，后者必须金额相符且留下唯一核对凭据。两种状态分开，不伪称银行或支付机构已验签。没有自动扣费或自动续费。

同档续购和跨档切换统一从已有未撤销服务的最晚到期后接续；不把基础两个月直接折换成年卡，不自动计算补差价。立即升级与部分退款本版不支持，界面明确下一服务期生效。取消待处理订单不影响现有权益；撤销权益不代表完成退款。所有撤销均留原因和审计。

按 Asia/Shanghai 自然月计算开始/结束（统一保存UTC）。1月31日加1月钳制到2月最后一天；2月29日加12月到次年2月28日。生效区间为[start,end)，在end时点即到期。过期后保存订单、历史消息、用户跟踪配置；停止新付费处理，不删除原来的个人资产。不同账号绝不互看。

用户网站线索和审核

免费及付费用户均可提交公开网站；表单为网站名、URL、机会类别、补充信息，以及“同意核验公开网址并作为平台来源使用，个人身份和需求不公开”的明确同意。不接收账号密码、Cookie、带令牌的私密链接。不自动抓取提交地址。

自动步骤：校验URL、去追踪参数、按规范化完整URL去重、按用户限频、落库、立即进入线索审核列表、给用户回执。不同用户提交同一地址只建一个线索，保留各自提交记录，用户看不到其他人的身份/要求。

审核采用整体通过/退回补充/拒绝，不制造几十个字段审核。审核界面同时提供用户线索入口和原机会审核入口，二者不混淆：通过线索仅允许登记采集来源；通过原机会审核才允许正式发布。

通过时记录公开采集说明、核实后的公开地址、来源信任等级、审核原因。用户原始补充内容不得直接拼入模型指令；维护员批准的公开说明才供采集使用。非官方来源可作为发现线索，不能被自动盖上官方认证。

来源采用现有 p.add_source（规范化URL幂等）；新任务采用 p.create_task 的固定 request_key，保留原限额、连接、域名与权限校验。不自动提高WMA并发。登记来源与创建任务分开；不会因审核员点通过而自动产生费用。登记动作本身保留原接口返回的启用状态，原SourceProfile默认值仍属R2接入必验项。

定制跟踪闭环

用户订阅有效且含site_watch → 选择本人已通过线索 → 占用一个网站名额 → 等待维护员明确启用 → 生成持久任务 → 登记/复用来源 → 创建原WMA任务 → 原系统回收候选并进入原机会审核 → 原审核后才会进入机会总览。

跟踪记录展示待接入、待执行、正在处理、已有结果待审核、失败、暂停等状态，不能把QUEUED当采集成功。按固定任务标识防重复；失败不无限重试。每次实际派发前重新核查订阅、来源、维护员角色与DNS安全。过期或撤销停止后续新任务；已经远端启动的任务不能声称已撤销远端成本。

主题跟踪只扫描既有已发布机会，读取 p.catalog 的版本分页；全量一轮完成才发消息。目录版本中途变化或超过扫描上限，保留错误/续查说明，不标作完整成功。以机会ID+版本+跟踪规则去重；首次扫描可呈现现有结果，不反复生成相同消息。不把关键词主题筛选称为新资格判断。

数据与安全

新增表独立前缀mbr_，复用现有SQLAlchemy引擎；不改既有事实、画像、发布表。升级显式执行，不在GET/应用启动时自动建表。金额、订单、授予、幂等记录和审计同事务；轻量写锁串行化短事务，避免并发双开通/超额；网络调用不得持有数据库写事务。

URL只接受http/https，默认标准端口，拒绝IP字面值、点分数字伪装、回环、本地域、内网、账号密码、控制字符和敏感查询参数。提交时仅做字符串/结构检查；实际派发前检查全部DNS结果，任何非公网结果拒绝。模块本身不发HTTP抓取请求。WMA网络隔离和重定向/DNS重绑定控制仍须在实际采集执行环境验收，不能把一次DNS检查说成完整SSRF防护。

复用原登录Cookie和写操作CSRF；前端不得传username来决定当前用户。每个读写端点鉴权；同源限制、安全响应头、请求体上限。公开渲染使用textContent/转义，不渲染用户HTML。站点反馈、订阅管理均有审计与请求幂等。

验收与不包含

自动测试需覆盖自然月、金额、改价/下架快照、重复确认、跨账号越权、审核权限、CSRF、URL恶意输入、限频、去重、订阅到期、名额、采集幂等、目录版本冲突、任务状态、浏览器窄屏及交互。独立模块测试不能代替R2回归。

不包含：真实微信/支付宝收款、代扣、自动退款、消息外部通道、私人登录后网站采集、承诺覆盖全部网站、真人手机验收、PostgreSQL实机迁移、真实WMA供应商付费调用、线上部署。

SECTION 02

定价、服务差异与运营设计

为什么保留这三个档位

基础订阅服务一次集中机会窗口，因此采用2个自然月而不是强迫长期绑定；深度订阅服务全年多个阶段，以12个自然月减少重复设置的负担，同时给更多主题。这里的“深度”并不表示给免费用户较差的事实或给年费用户虚构的高资格分。

定制订阅卖的是“指定公开来源的可交付跟踪范围”，不是“用户给任何网站都能保证抓取”。先说明关注目标和网站，经核验可行性后报价；服务单写明期限、网站名额、主题名额和可交付事项。用户确认后才能开通。

公共机会始终免费。用户通过免费页找到合适机会不是需要惩罚的“揩油”，而是产品完成了价值交付。付费动机应来自省去反复检查的成本，而不是制造信息壁垒。

首轮默认值不是商用定价结论

基础29.90元/2个月，深度129.00元/年，只作为便于产品验证的初始假设；均为草稿，没有自动上架、收款或市场验证。定制不预填价格，必须逐单报价。后台可修改这些数字，不能把本包默认值当成成本已覆盖的证明。

初期应先完成少量真实来源的试运营，再评估：每次成功发现机会的实际API与人工成本、每位用户的主题规模、来源重复利用率、用户阅读提醒/采取行动的比例、因误报或延迟产生的投诉、到期是否进入新机会窗口。不得用“连续点击天数”代替真实价值。

把轻量目录检查与昂贵调查分开

扫描已发布目录与让WMA重新调查网站，不是同一成本等级。实现中已经分开计时：深度/定制的公开目录目标每6小时检查；定制网站调查默认每24小时，后台可调到24至720小时。调度还需维护员授权。

纯算术示例：3个网站、每6小时一次、60天，会形成最多720次候选调查机会；改为每24小时是180次。这里的60天只是测算期，并非代码把2自然月固定成60天；数字也不是实际调用账单。网站去重、没有新增时只做轻量检查、不同用户共享已发布结果，应作为后续基于真实采集能力的优化方向。本模块不会声称已经实现了全平台按来源合并付费调查。

定制报价至少审视：预计调查次数×单次实测成本 + 异常恢复/审核人工时间 + 基础设施和通知成本分摊 + 售后与退款预留。没有真实成本之前，不应承诺无限网站、无限调查或极短响应时间。原WMA预算/队列/连接策略保留，不被会员模块绕开。

对用户说清楚什么

时间按北京时间自然月计算；既有服务续购/换档从下一期接续，不在中途凭空损失剩余时间。已支付/试用开通与待确认申请明显分开。停用跟踪释放活动名额；到期保留历史和配置，但不继续产生新的付费任务。

同一公共网站可同时被不同用户建议。用户身份和个人备注不对其他普通用户公开；核验后的公开来源可供全平台使用。这一点在提交前明确同意，不应先收集后偷偷将私人定制内容公开。

目标间隔不是第三方网站或供应商的服务保证。界面显示实际检查/任务时间、失败或待审核状态。任务排队、结果回收、机会整体审核通过是不同阶段，不能统一标成“已完成”。

权限与运营分工

维护员拥有审核和服务管理权；普通审核员只能处理网站线索。付费等级不增加管理权限。

试运营先使用赠送试用验证功能。人工核对外部付款仅用于有真实商户凭据的运营流程，必须核对金额和唯一凭据；系统本身不连接银行，不做支付验签。计划接入官方微信/支付宝时，应另做真实交易/回调验签/金额商户订单匹配/幂等/退款对账验收，不能让用户点击“我已付款”直接开通。

自定义服务项目分为系统已实现的自动能力和人工履约说明。添加一个服务名称不会自动创造新的算法、人工团队或通知渠道；后者需要实际交付安排。

SECTION 03

运行、接入与运维说明

1. 本机演示：最短路径

Windows 解压后运行根目录 Start_Demo.cmd。也可在 PowerShell 中逐条执行：

py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install .
.\.venv\Scripts\python.exe -m deepaha_membership.demo --data .demo --port 8765

浏览器打开 http://127.0.0.1:8765/membership。每次启动生成新的随机密码，旧会话失效；订单和设置保存在 .demo/demo.db。同一演示进程内模拟来源/任务状态有效，重启后模拟队列内存不保留，不能用于真实运营。重新体验全流程时使用一个新的演示目录，例如 --data .demo-second。

本机演示严格只监听127.0.0.1。它不是给手机直接访问的局域网服务器，更不是公网认证服务。可在电脑浏览器的设备模拟中看手机布局；真实移动浏览器需要完成宿主HTTPS接入后验收。

依赖中包含tzdata，避免Windows没有IANA时区数据而无法计算北京时间。Python官方说明：https://docs.python.org/3/library/zoneinfo.html#data-sources 。本次仅在Linux/Python3.13.5执行测试，没有运行Windows批处理。

2. 推荐体验顺序

先以 maintainer 登录，进入“服务管理→套餐价格”，核对三种草稿套餐再上架。切换 alice，申请基础订阅；再由 maintainer 在“申请与报价”选择“赠送试用”，最后回到 alice 查看服务周期并新增跟踪主题。

网站流程用 bob 演示：先申请定制、等待维护员填写报价、由 bob 确认，再由维护员赠送试用。bob 提交公开网站，reviewer 整体通过；bob 在网站建议中加入定制跟踪；maintainer 登记来源、明确启用，再到跟踪任务安排和交接。演示提供“模拟结果返回”，只会转为“已有结果·等待整体审核”，不会伪造正式发布。

所有新增接口位于 /api/membership。GET /plans、GET /info为公开读取；其余需要原登录。写操作需要原 deepaha_session Cookie 与 X-CSRF-Token。前端不提供username来决定当前用户。POST/PUT数据使用严格模型，多余字段拒绝。

接口族 作用 权限
/me、/orders、/orders/{id} 个人权益、订单、报价确认、取消申请 本人；单订单允许维护员查看
/manage/plans、/manage/services 创建方案、发布条款新版本、上下架、服务项目 维护员
/manage/orders/{id}/quote、confirm 定制报价、人工/试用开通 维护员
/manage/grants/{id}/revoke 撤销权益，不代表完成退款 维护员
/submissions、/{id}/supplement 公开网站建议、本人补充 登录用户
/review/leads、/{id}/decision 整体线索审核 审核员或维护员
/manage/leads/{id}/adopt、enable 登记/复用来源、明确启用 维护员
/watches/topics、/watches/sites、/{id}/toggle 建立/暂停/恢复本人跟踪 有效权益 + 服务端名额检查

/manage/audit 最近操作记录 维护员

原接口适配

ProductPort调用原 p.add_source、p.source_status、p.create_task、p.task_detail、p.catalog。来源归属的已发布机会查询读取原 Identity→Opportunity→CatalogTarget，并通过原 _target 生成公开投影。它不依据域名相似度猜来源，不把未发布候选当机会。

状态

订单：基础/深度 PENDING → FULFILLED_TRIAL / FULFILLED_MANUAL；定制 REQUESTED → QUOTED → 用户确认PENDING → 开通。待处理可取消；报价过期必须重报。

线索：PENDING → APPROVED / NEEDS_INFO / REJECTED；本人补充将待补充重新转为待审。通过不会创建采集任务、不会发布机会。

任务：QUEUED → DISPATCHING → CORE_QUEUED / RETRYABLE，原任务回读可进入运行、失败、需恢复、取消或 RESULT_PENDING_REVIEW。未知返回不是成功，不自动无限重试。后续从原已发布投影产生独立机会提醒。

权益不是前端标签：由未撤销的持久grant和[start,end)时间范围动态判定。旧方案快照不被改价覆盖，续购不重置当前期。降档后的超额配置保留，但按稳定顺序只执行新额度内的活动项；用户可暂停旧项调整名额。
