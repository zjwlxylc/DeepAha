# DeepAha 全模块体验改善 Implementation Plan

> **For agentic workers:** 使用 superpowers:executing-plans 或 subagent-driven-development 按任务执行；本交付仅提供参考实现与任务计划，不授权修改主线或部署。

**Goal:** 在不重建 SG8-A 业务内核的前提下，把当前产品改成更容易发现、判断、行动、审核和维护的界面。

**Architecture:** 保留 `deepaha.product`、现有同源 API、权限与证据链。先替换前端信息结构；列表查询、画像 PATCH、个人事项和调度策略另行扩展。生产客户端不使用原型的本地状态机代替后端事实。

**Tech Stack:** 沿用当前 Python/FastAPI/SQLAlchemy 与 `web/public/product` 原生 JavaScript/CSS。离线原型为零依赖 HTML，仅供布局与交互参考。

**Spec:** `00_DESIGN_BRIEF.md`、`01_全面审核与产品改进方案.md`、`03_API与页面接入对照.md`，以及根目录 `DeepAha_全模块交互原型.html`。

## 全局约束

- 审核仍然只做整份返回的整体通过/不通过，不恢复逐字段人工审批。
- WMA 只生产候选内容，不能批准正式事实、规则、Eligibility 或公开发布。
- 资格、推荐价值与时间状态分离；不把原型的简化判断复制进生产业务。
- AGENS 按项目策略串行；其他绑定未经真实验证也串行。不得通过浏览器 `verified` 字段获得并发权限。
- 秘密只由正式宿主环境注入；正式网页不新增输入或读回真实 Key 的通道。
- 原型数据、字标、内联脚本与身份切换工具不能直接部署；公司图形 LOGO 继续用 `brand-logo.png`。
- 单任务窗口；每个 Slice 最多三轮自修复；未验收不合并；合并只采用用户批准的 ff-only 路径，不重写他人提交。
- 本计划不包含支付开发、人格测评、独立 Ops Gateway 修改和生产服务器操作。

## Review Focus

1. **未显示的画像字段、显式清空与跨标签页编辑：** 由 A1 测试，禁止部分 PUT 清空其他资料。
2. **第 51 个以后的来源与筛选后的总计：** 由 B1 测试，禁止只查当前页却显示“没有来源”。
3. **提交时内容版本或来源政策改变：** 由 A3、B2 测试，不得绕过 409 或重复批准。
4. **远端已收到请求但本地超时：** 由 C1 测试，禁止自动二次 prompt；恢复文件与重新调查分开。
5. **窗口缩放、键盘、长文本、低带宽与误点击：** 由 A0/A2/A3 测试，输入不丢、按钮可辨、焦点可回、不可重复提交。

## 先后关系与取舍

| 批次 | 任务 | 改动性质 | 放行要求 |
|---|---|---|---|
| A | A0–A3 | 已有能力的安全接入与前端改善 | 不改变核心资格、审核和事实结果；原业务测试回归 |
| B | B1–B3 | 有限 API/数据扩展 | 新旧接口兼容；数据保留；增量迁移与回退 |
| C | C1 | 连接能力和受控并发 | 隔离真实验证、原子领取、不重复 prompt、可退串行 |
| D | D1 | 真实用户任务验收 | 独立记录；不能以合成演示代替效果证明 |

先交付 A，B 可按来源规模与用户反馈排优先级；C 不阻塞界面上线，失败时继续串行。B3 的个人清单可以延后，正式页先使用已有备注。不要为“一次全做完”把所有模块塞进一个不可回退的大提交。

## A1｜画像安全保存与个性化入口

**修改文件：** `user.js`、`birth-date.js`；`personal.py` 第一轮可不改语义。**拟新增测试：** `backend/tests/product/test_profile_update_contract.py` 仅当扩展后端；前端增加画像合并用例。

- [ ] 详情“补一项”导航回相应字段；不默认收集不相关的敏感信息，不把“不填写”变成不符合。
- [ ] 同步“关闭个性化”“导出”“清除”的界面。清除成功后撤销缓存中的个人判断，不删除公开数据。
- [ ] 验证请求体和真实服务返回；明确记录完整 PUT 暂不解决跨标签页覆盖。版本化 PATCH 放 B2。

可直接用于前端测试的最小期望：

```js
const original = {major:'广告学', certificates:['CET6'], cities:['宁波'], birth_date:'2006-10-01'};
const submitted = {...original, team_size:4, birth_date:''};
assert.deepEqual(submitted.certificates, ['CET6']);
assert.equal(submitted.major, '广告学');
assert.equal(submitted.birth_date, '');
```

此例只是合并断言；不能把它误当已经测试后端并发。

- [ ] 测未知绑定与 AGENS 强制 1；客户端伪造已验证不生效；换 Agent 发布绑定会失去原并发资格。

- [ ] 模拟进程在 create、upload、prompt、download、ingest 各阶段退出；检查原件、远端标识、重复接收幂等与最终状态。

**必须停止而非自作主张的情况：** 无真实凭据、没有授权的调用预算、供应商能力不明确、原子领取测试失败、prompt 接收状态不明。交付阻塞原因与已验证部分，不能用模拟结果替代。

## D1｜真实使用验收与分批发布

**参与对象建议：** 招募少量自愿体验用户，覆盖新用户、已有画像、关注不同机会类别；另由审核员和维护员各完成典型任务。人数按实际可招募决定，不把样本少包装成统计显著。

- [ ] 用户任务：从总览找到一个具体机会；说明自己有何条件待确认；找到官方入口；收藏并记录下一步。
- [ ] 审核任务：面对有备注、硬阻断和版本变化三类返回，正确作整体决定而非逐字段处理。
- [ ] 维护任务：从异常源定位到任务；正确区分恢复文件与重新调查；识别哪些配置会产生新的远端调用。
- [ ] 记录完成/失败、耗时、误解点与用户原话；同意参加不等于同意把敏感画像交给外部模型。
- [ ] 人工确认后走当前 staging/发布流程，独立资产版本、数据库迁移和并发开关分别回退。禁止现场改 production 源码；不改变隔离 staging 和 Ops Gateway 范围。

## 回归命令与证据要求

本交付可复现的原型检查：

```powershell
node --test tests/domain.test.cjs
python tests/build_single.py
python tests/browser_qa.py
```

最后一条需要 Python Playwright 和 Chromium；环境方法详见 `04_验证报告与使用限制.md`。它不运行原仓库业务测试。

原仓库继续开发时，至少执行当前 AGENTS 指定的验证。逐个测试文件运行可以用如下脚本，避免总进程通过掩盖个别返回码：

```python
from pathlib import Path
import subprocess, sys
files = sorted(Path('backend/tests/product').glob('test_*.py'))
if not files:
    raise SystemExit('未找到产品测试文件，请确认位于仓库根目录')
failed = []
for file in files:
    result = subprocess.run([sys.executable, '-m', 'pytest', str(file), '-q'])
    if result.returncode:
        failed.append(str(file))
print('FAILED:', failed)
raise SystemExit(1 if failed else 0)
```

另执行 `python -m compileall -q backend/src backend/tests/product`，以及当前仓库的 product/SG7 前端契约、独立 Gold Oracle、迁移 harness、静态部署契约和 HTTP smoke。首次执行先从 AGENTS 与脚本目录确定具体入口；不伪造本计划没有核验过的脚本文件名。
