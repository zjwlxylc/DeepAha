# 公告规则对指定岗位的适用性审阅

本批承接 PR #21，仅记录独立适用性决定及后台入口，不修改资格内核、旧快照或冻结 WMA 数据。

读取时指定当前目标 plan_id 和来源公告 rule_preparation_id / candidate_id。服务在同一事务中复核两端身份、事实集、共同 EvidenceCheck、规则准备与实际批准记录；来源必须是同调查、同公告版本的 OPPORTUNITY 规则，目标必须为该公告的确切岗位。返回完整绑定上下文及其摘要、来源规则和可选择的本来源包原文块。

保存提交上下文摘要、上一决定 ID、APPLIES / DOES_NOT_APPLY / NEEDS_ADJUDICATION、原文块引用及理由。适用和排除均要求至少一条当前原文块及字面引文，待裁决可不填证据但必须说明原因。可使用本来源包其他正式材料说明适用或例外；机械引用成立仅证明文本出处，语义决定仍属于独立审阅者。服务不能代签或把没有找到条件理解为排除。

每个目标计划与来源规则形成追加历史，当前 task 锁串行化；更正必须引用当前上一决定，防止覆盖他人刚提交的记录。相同人员、幂等键及请求重试返回同一决定；过期上下文、错误 predecessor 或跨任务引用拒绝保存。数据库保护 UUID、关联、请求/上下文摘要、实际审阅账号及不可变历史，历史存在时不允许降级删除。读取每条历史时检查其摘要和关联，旧记录不修改。

私有 API 与页面复用后台鉴权、private/no-store、原件入口及稳定重试方式。页面明确显示来源为公告、目标为具体岗位；不预选适用或排除，待裁决及旧版本不可被隐藏。当前记录不会被现有快照读取器或资格计算器消费，也不会解除 HUMAN_SCOPE_REVIEW_UNVERIFIED。

验收包括公告/岗位真实 PG 合成准备、适用/排除/待裁决及更正、丢失响应后重试、并发前驱冲突、跨目标/跨任务、证据篡改与过期、SQL 不可变及历史降级、私有 API、组件与桌面/手机浏览器。先完成服务及持久约束，再接页面；独立检查及同一候选必要 CI 通过后合并。所有 fixture 均为工程证据。
