# 调查规则候选与独立审核实施计划

目标：将已保存的审核事实接入独立规则审核，保留全部来源条件、真实证据锚点与未处理项。本地实现 IMPLEMENTED，候选 CI 和合并待完成；基线为字段 PR #15 与规则类型修复 PR #16 合并提交 0add01d。

采用当前 PostgreSQL、FastAPI、Next.js 与版本化 P9-B 契约。旧 b56f9b5 仅提供局部代码和测试参考；不整批合并，不接入其 UnitPlan 或后续覆盖平台。沿用用户授权在本任务连续实施，按实际风险使用测试和独立复核。

## 实现边界

- 不调用 WMA，不修改冻结 Schema、Prompt、原件、原始事实或引文定位。
- 只有当前归属、当前事实准备和 ACTIVE 审核事实集可生成规则候选；共同核验必须在缓存命中和每次决定前重放。命令 check_id、准备摘要、机会/岗位版本和来源集合均需一致。
- 所有已审核事实与原始条件保留分母。UNKNOWN 或不能执行的字段保留原因，不自动生成规则。规则批准不产生资格结论、UnitRuleSet 或公开目录发布。
- 人工逐条评估全部真实 EvidenceRef 的权威层级、支持/冲突关系、实际生效时间及是否适用于精确目标。无默认批准、无默认权威或时间；未解决项不得冒充已核对。
- NEEDS_ADJUDICATION 可追加最终决定并保留历史；最终决定不可反转、重复或被缓存掩盖。追加记录与 P9-B 决定在同一事务提交。
