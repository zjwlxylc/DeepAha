# 条件适用范围与例外的后续集成顺序

状态 PLANNED。承接受信条件快照与合成画像回放；本文记录当前代码缺口和下一批验收，不表示对应功能或真人审核已完成。旧分支 `delivery1-direct-wma` 的 b08d82a、e2b1043 等仅作参考，不能整批移植旧迁移和资格放行逻辑。

当前证据：

- `investigations/facts.py` 已允许公告级 OPPORTUNITY 和岗位级 UNIT 分别形成事实集；`field_mapping.py` 明确拒绝把单位组当岗位事实目标。
- `unit_manifest.py` 保留公告、本组、本岗位条件及其他目标排除清单；父级条件尚未连接其实际批准事实及规则，不自动继承。
- `unit_snapshots.py` 每次重建核对当前事实集、审核记录和证据。来源完整性与备注始终保留阻塞；纯内核还保留完整范围未审核阻塞。
- 当前回放能证明逐规则满足/冲突/缺失，不证明未遗漏例外。不能为了得到 ELIGIBLE 或 INELIGIBLE 而先移除这些阻塞。

实施顺序：

1. **公告通用条件对精确目标的适用性。** 先关联当前公告事实集及独立批准规则，再记录独立审阅者对特定岗位版本的适用、排除或待裁决结果。每次决定绑定来源和目标 preparation / fact set / check 的实际 ID、摘要、原文证据及理由。排除必须有依据，“没有找到”不能推断不适用。记录采用追加历史、幂等重试和读取时复核；旧记录保留原义。
2. **继承结果进入新版快照。** 显式保留父级 source fact / rule / approval 与岗位 applicability 记录；不复制成原生岗位事实，不改写已批准来源规则的身份。新契约和适配器版本与旧快照分开；新旧记录均不得单凭 JSON 自证可信。先维持整体不确定。
3. **单位组、原件范围与例外。** 按当前实体关系增加单位组事实目标，不能借用任一岗位 ID。审阅正式附件、原始备注、未知/未处理/冲突及条件遗漏，并将例外挂到正确来源和目标。Word UNVERIFIED 仍是独立证据缺口，不能靠范围签字改为机械 PASS；本计划不包含 DOC/OCR 平台。
4. **完整条件与时间边界的独立验收。** 审阅全部原件、条件分母、适用/排除、例外、变更及有效期，生成可复查版本。仅有逐字段或逐规则批准不足以满足本步。移除特定限制必须有独立契约、失败用例和真实批准依据，不能增加调用方 `complete=true` 开关。
5. **再次回放后才接个人薄链路。** 含父级继承、排除、例外、过期、撤销、错岗、未知与资料缺失；确定性否定仍要求官方证据和已解决的适用范围。实际个人 API 使用已有画像归属与授权检查，不能把任意客户端画像当正式状态。

每批先做可重复失败样本和最小实现，再接桌面优先的私有审核页面；复用已有证据查看及重试方式，不新增一套调查/解析/资格系统。相同候选必要检查通过后分批合并，不以单批工程通过替代整体发布资格。下一批具体从第 1 项开始，不同时扩展上述全部范围。
