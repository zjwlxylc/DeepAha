# 真人审核易用性迭代

用户反馈：现有工作台在逐步说明下仍无法理解和完成。本轮暂停真人验收，先改进实际界面；此前 CI 和合成回归不能证明可用性。

## 决策

不继续修补长操作说明，也不把旧表单改成更多折叠面板。新增普通审核入口：搜索并明确选两个真实岗位 → 一次核对身份 → 按岗位逐条核对原文 → 按条件逐步回答独立规则问题 → 待处理清单。旧页面保留为管理/追溯入口。

常规页面不暴露内部 ID、事实集、准备版本、JSON 和术语下拉框。身份候选值可供核对，绝不预选本人批准；每个决定必须来自本人回答和明确提交。原服务、角色、证据优先级、版本冲突、回执和晋升门保持。准备材料及规则只由清楚标注的按钮触发，不自动运行 WMA。

字段审核采用原文/解释对照和逐步问题：是否支持、是否适用于当前岗位且无未解决冲突、最终决定。看不懂、原件打不开或证据不清楚均可明确记录待处理；不得为了让流程走完降低批准门。规则权威、支持、目标和时间分步回答；时间使用分开的日期、时间控件和明确北京时间提示，不把缺失时间补为零点。

两个岗位先统一登记再整理候选，避免新增第二岗位让第一个岗位审核版本失效。新入口不允许局部表单替换整套既有归属。字段与规则草稿沿用当前窗口内存，绑定版本，页面换对象后仍可恢复。成功后显示已保存及明确下一步，失败不自动跳走。

## 文件与实施顺序

1. `web/lib/guided-review.ts`：纯函数导航、规范值/定位解释及问题映射，先写契约测试。
2. `web/app/review/investigations/[taskId]/check/page.tsx` 与 `components/investigations/guided-*`：选两个岗位、批量身份表、当前一题、结束清单；复用已鉴权工作台读取及原 actions。
3. `actions.ts` 增加新页面失效；队列/工作台默认入口指向向导，旧深链兼容；`globals.css` 使用原品牌令牌、44px 触控、响应式原文对照。
4. 合成浏览器场景从选岗到身份、字段与规则问答、待处理、回读，覆盖 390px/桌面、键盘、200%布局、错误与重试；检查截图，再把真实环境更新为同一代码。

## 验收

- 不读外部操作说明，首屏能看出“选两个岗位”和唯一继续动作；不要求先了解内部对象模型。
- 任一时刻只需回答当前问题，不预选原文支持/无冲突/规则批准，不以隐藏值替本人作判断。
- 未决项可继续其他项目，但保留真实记录与全对象分母；未提交的普通浏览不能成为审核完成。
- 两岗位身份由同一事务或原追加服务保存，不覆盖原归属；原件、原决定及证据哈希不改写。
- 技术验证通过后再邀请用户做真人验收；没有用户成功完成的证据前，不宣称平台已可用或 R1 真人闭环完成。

本轮不实施 Scout、资格范围晋升或发布；不执行真人批准；pytest 仍仅允许隔离库 55437，禁止真人持久库 55439。
