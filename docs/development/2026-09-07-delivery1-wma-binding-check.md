## 首次发现时的结论和处置

发现影响真实校准有效性的接入问题：沿用 PoC 的 `ManifestBuilder.id/name/version → runtimes.create → sessions.default` 路径，只能证明创建了具有该标识的运行，不能证明使用了后台已发布调查 Agent 的完整配置。

本次通过供应商控制面只读查询，取得当前发布 v1 和 `wma-zjhr#4` 历史真实会话的配置。前者包含系统提示词和 6 项技能，后者的 `agentManifest` 中没有这两项。当前主仓适配器仍使用相同的基础 manifest 创建路径。此前交付一的模拟 SDK 测试没有覆盖这个差异。

因此本批恢复为 **IN_PROGRESS**：本地回收、校验、存储和页面工程候选保留，但 Direct WMA 发布配置绑定需要修正。未宣布或重开任何原有阶段的 Engineering Gate；没有修改既往测试或失败证据。真实调查校准和发布资格仍未完成。

按负责人“出现重大问题时停止”的要求，暂停新的真实调查及交付二实现。已在本地运营 CLI 的 `run` 入口加入 `WMA_PUBLISHED_AGENT_BINDING_UNVERIFIED` 阻断，在访问数据库、领取任务和创建 Runtime 前返回。`preflight` 显示该原因；`show` 和原 Runtime 的只读回收保留。这个阻断不是根因修复，也不能通过填一个版本号或开关绕过；底层适配器仍待改造，不应直接绕过 CLI 调用。

## 恢复真实校准前的最小修正

1. 在现有适配器中区分控制面 Agent ID、manifest 标识、业务发布版本和 manifestVersion。通过只读接口精确解析当前发布记录；草稿、停用、歧义匹配及版本变化应明确失败。
2. 使用能实际加载已发布 Agent 的会话创建路径。保持已核到的业务模型和发布配置，不同时换模型、Prompt、Schema 与 SDK，不另建调查平台。
3. 在远端会话创建后、调查 prompt 前，读回并核对实际配置。至少比较系统提示词、技能及可取得的模型/发布版本证据；未能核实的字段保持未知，不能把后台配置记录当运行回执。发布版本在创建期间变化时拒绝混合记录。
4. 在执行器中分别持久化已取得的 Runtime 与 Session 标识，防止新增会话绑定步骤失败后丢失已创建运行。失败不发调查、不自动重跑；恢复仍只回收原任务产物。
5. 先做模拟协议反例，再在既有授权与费用边界明确后做一次有界真实绑定检查。只有会话配置读回符合预期，才对固定 ZJHR 公告发起一次调查，并保留真实原件与子项分母。
6. 人工摄取审核和逐字段事实审核分别保留。未经人工操作，真实任务止于待审核；不能通过测试身份或运营代理签名补齐事实批准。

验收须证明：公开/数字 ID 不混用；空 manifest 或缺系统提示词/技能时不发 prompt；版本变化不悄悄换版本；配置包含 secret 时日志及证据只输出白名单；部分创建失败能保留恢复标识；真实会话与选定发布版本之间有可核对关系。金额硬上限仍未由 SDK 提供，本轮未核验现行价格，不能声称实际调查免费。
