## 原件出处

### 公告接口

[用户批准的聚合页](https://www.zjhr.com/010/client/index6.jsp?column1=8a1293669fcdab3c019feff272232edc) 的页面脚本明确使用 `guestService/guestServiceAction!getTable32ByColumn1.action`，POST 参数为该公告的 `column1`。使用正常页面会话、Referer 和 XMLHttpRequest 请求头读取同一公开接口，响应为 `text/plain;charset=utf-8`，内容为 JSON。新鲜响应 31268 字节，与冻结 JSON 的字节及 SHA-256 完全一致。

因此当前文件有原始接口响应依据，不是仅凭 JSON 外形推断其为原件。页面声明的公告地址与实际接口地址仍是不同地址；本次复核没有追溯改写交付中的 `AGENT_DECLARED`。终端一度显示乱码，经 Unicode 和字节核对确认原文件中文标题完整，读取器不进行猜测性编码修补。

## 读取边界

- JSON 只支持明确的单行公告接口结构，保留字段路径和内嵌 HTML 节点定位；拒绝重复键、多行混淆、非有限数、非法字符与任意模型 JSON。标题或正文出现替换字符时保留异常，不自动修复后通过。
- DOC 通过固定镜像中的 Antiword 读取为 DocBook。容器无网络、只读根目录、非 root、有限内存/进程/时间，原件仅通过标准输入传入。镜像 ID 是读取器版本的一部分，原 DOC 的哈希仍为证据锚点。
- DOC 阅读结果不提供 Word 页码或排版等价保证，所有该格式的引文核对均要求真人检查，不自动获得机械核验 PASS。无法读取的结构、转换告警和错误按稳定原因返回。
- 正常启动准备并缓存阅读镜像；没有配置 `DEEPAHA_DOC_READER_IMAGE` 的其他环境仍将 DOC 标为不支持，不能宣称这些环境也已经部署了该能力。历史回放需要保留对应不可变镜像。
