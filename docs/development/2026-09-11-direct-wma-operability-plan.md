# Direct WMA 官方机会调查可操作性补齐

基线：PR #50 已合并，main `6a480e7bbe968cc51d88ad76fdaf553bc0a59661`；既有预检与审阅成果保留。用户已授权实现以下三个依赖批次及一次必要的真实 WMA 调查验收。当前文档是实施计划，不是验收完成记录。

## 目标与边界

一键启动进入 `/review/investigations`，用户无需命令行或后台补数据，能准备来源、明确发起调查、了解进度与失败原因、查看原件，并进入现有证据、身份、岗位条件和范围预检。沿用 WorkBuddy 已发布 Agent 与模型配置；不修改远端配置，不无限重试，不回退旧模型直连线路。

保留持久数据、冻结原件、历史结论及未跟踪文件。独立真人审核必须由符合职责的人实际完成，Codex 不代签、不切换身份伪造独立审核；整体资格保持 UNCERTAIN。本地体验不构成 Gold、STABLE 或生产资格。

## 实施批次

1. **启动与就绪**：复核 `scripts/local-manual-test.ps1`、浏览器启动器、身份初始化、来源注册表及 WMA 凭据机制；提供准确的登录、数据库、处理进程、可用来源、配置与连接状态。可重复初始化至少一个有当前官方依据的具体来源，不批量升级 LINK_ONLY，不以放宽筛选制造可选来源。默认启动不发起调查。
2. **页面与持久调度**：复用 `investigations/runner.py`、`store.py`、`wma.py`，补充页面明确发起、持久意图及处理进程；任务和操作者、配置绑定可追溯。防重复提交；重启后识别已知远端任务、未知执行结果和可恢复材料回收，不盲目重新发出 prompt。页面显示阶段、更新时间、安全失败原因及适用恢复入口。
3. **实际材料与审阅衔接**：串联任务详情、原件核验、身份/岗位、字段与规则、跨层条件及预检，依据实际状态提供下一步和不适用说明，避免手填内部 ID。通过真实启动入口发起至少一份真实公告调查，保存新任务/版本/结果证据；独立真人审核确有阻塞时如实标记。

## 验证与交付

- 先建立有意义失败样本，再最小实现。普通 CI 使用模拟远端 WMA，但走真实初始化配置、API/数据库和后台调度入口；不自动消耗真实模型额度。
- 覆盖空来源、缺少会话、未配置、重复发起、并发、重启与未知结果；保留原有回归。真实 WMA 验收独立记录，不用模拟结果替代。
- 按依赖分 PR；各候选九项 CI 成功且合并同树后交付。文档提供从启动入口开始的准确中文点击步骤、实际到达阶段和未通过边界。
- 暂停完整范围签署、例外执行、解除资格限制和个人薄链路扩展；选择性 CI 与历史临时目录清理不属于本批主线。
