# DeepAha Windows 本地人工体验

## 开始与停止

1. 双击仓库根目录的 `启动 DeepAha 本地人工测试.cmd`。
2. 等待依赖、持久化 PostgreSQL、迁移、审核身份、API、调查处理进程、Web 和浏览器检查完成。
3. 使用启动器打开的浏览器进入 `/review/investigations`。其他浏览器不会共享它的审核会话。
4. 使用结束后双击 `停止 DeepAha 本地人工测试.cmd`。

普通启动只准备本地环境，不访问官方来源、不发起 WMA 调查。首次启动可能需要下载依赖、镜像和 Chromium。

## 从来源到调查

1. 查看“调查启动与就绪”，确认登录、数据库、处理进程和可用来源。
2. 尚未配置时，在“配置 WMA 连接”填写企业密钥、已发布 Agent 标识和调用方，保存后点击“检查 WMA 发布连接”。模型沿用 WorkBuddy 后台配置，页面不修改模型。
3. 选择已批准来源。四个用户指定的 zjhr 页面保留官方聚合源身份；另提供第一份公告对应的省人社厅一手原文。选择来源后自动填写公告地址、调查说明和已知附件。历史样本不代表现在仍可报名。
4. 核对范围与执行时间上限，点击“登记调查任务”。登记不会启动远端调用。
5. 点击“查看已登记任务”，再明确点击“发起调查”。处理进程按已记录的配置版本执行一次有上限的调查。
6. 刷新任务详情查看阶段、更新时间、材料和错误原因。结果不确定时不重新发出 prompt；已有远端会话且无活动执行时，可点击“恢复材料”，仅下载既有材料。

连接检查过期后，新请求需要重新检查；已明确发起的请求仍使用原配置版本。配置替换不会让排队任务静默改用另一 Agent。重复请求回执不会造成第二次调用，历史任务也不会在进程重启后自动无限重试。

## 从材料到审核

任务详情按当前状态显示下一步：原件、文档证据准备、身份/岗位、字段与规则、跨层条件和范围预检。先在规则审核中整理条件快照，再通过“查看条件快照”进入后续页面，无需手填内部标识。

不支持解析的附件仍保留原件。运营人员可以填写理由，明确排除其文本解析要求；系统保留无文本的整文件引用、操作者与材料版本。该决定可以撤销，不代表附件内容得到验证，也不能据此批准字段、完整范围或资格。未知条件、缺失材料和独立审核要求继续保留。

## 数据与身份

- PostgreSQL 使用工作树专属的持久卷，正常停止不删除数据。
- Direct WMA 原件保存在 `%LOCALAPPDATA%\DeepAha\manual-test\investigation-objects`；旧路线数据保留在原目录。
- WMA 密钥按配置版本经 Windows DPAPI 加密保存，页面不读回密钥，不放进命令行和运行清单。
- 本地负责人会话由启动器准备；重新启动不会覆盖历史审核决定。Codex 或验收脚本不得切换身份代替独立真人签署。
- 多个工作副本共用本机体验端口，不能同时运行。启动器不按端口结束未知程序；处理进程心跳还会核对代码目录，防止把另一份代码误报为当前环境就绪。

## 常见问题

- Docker Desktop 未启动：启动 Docker Desktop 后重试。
- 缺少 uv、Node.js 24 或 Corepack：准备对应依赖后重试。
- 端口被占用：先确认并关闭另一份本地体验服务，保留原数据。
- 没有审核会话：使用启动器打开的浏览器；会话失效时停止后重新启动。
- 连接检查失败：检查企业密钥权限、Agent 发布状态及服务可用性；不要把连接检查成功当作调查执行成功。
- 原件缺失、403、验证码或证据核验失败：查看明确原因；不绕过访问限制，不伪造材料。
- 启动中途失败：只清理本轮已核验拥有的进程和容器；日志与故障截图位于 `.deepaha-local-manual/`。

旧 `/review/human-test` 路线仅保留历史功能，不是当前默认入口。当地体验、原件完整性或一次真实 WMA 返回均不构成 Gold、STABLE、真人伙伴验证或正式发布资格。

## 开发验收选项

`-VerifyEntry` 通过真实启动浏览器核对可选来源与移动端布局，不发起外部调用。`-VerifyInvestigation` 仅在明确授权的真实验收时使用，经页面检查连接、登记并发起一项调查；本地回执防止重复创建，验收不自动批准材料。两者不是用户正常启动所需的操作。

完整数据清空仍须作为独立维护动作处理；正常停止不是删除，不执行全局 Docker 清理。
