# DeepAha Windows 本地人工测试

## 开始与停止

1. 双击仓库根目录的 `启动 DeepAha 本地人工测试.cmd`。
2. 等待窗口依次显示环境、依赖、数据库、迁移、数据、API、Web 和浏览器状态。
3. 浏览器会打开：公开机会、个人行动、反馈审核，以及独立的截止变化提醒测试收件箱。
4. 使用结束后双击 `停止 DeepAha 本地人工测试.cmd`。

用户不需要输入 Docker Compose、uv、pnpm、端口或环境变量命令。首次启动可能需要下载依赖和
Chromium，耗时会长于后续启动。

## 数据和身份边界

该启动器只创建许可安全、明确标识的合成工程夹具：

- 主浏览器上下文（Browser Context）包含一个合成个人身份，以及名称不同、权限独立的合成
  reviewer 身份；用于公开机会、画像、个人机会、行动、纠错和有限审核。
- 提醒浏览器上下文使用另一个合成个人身份，只用于 Phase 8 截止变化提醒。
- 明文临时会话只在被 Git 忽略的 `.deepaha-local-manual/` 中短暂存在；浏览器取得 Cookie 后
  删除身份文件，数据库只保存摘要。停止入口删除浏览器配置目录。
- 提醒投递目标固定为 PostgreSQL `TEST_INBOX`，没有真实邮件、短信、微信、小程序或推送供应商。

真人参与者保持 `0`。本环境不形成真人理解、信任、行动、留存、付费或发布资格证据；当前发布
决定仍为 `HOLD_MISSING_HUMAN_EVIDENCE`。

## 常见失败与恢复

- 提示缺少 Docker Desktop：安装并启动 Docker Desktop，然后重新双击启动入口。
- 提示缺少 uv、Node.js 24 或 Corepack：安装对应环境后重新启动。
- 提示资源被其他程序占用：启动器不会停止未知程序；请自行关闭明确占用者后重试。
- 启动中途失败：启动器会清理由本轮已验证拥有的进程和 Compose 资源；诊断日志保留在
  `.deepaha-local-manual/logs/`。
- 提示运行清单不属于当前工作树或资源标签不一致：启动器会拒绝清理。不要手工删除或改写运行
  清单；先确认是否移动了工作树或是否有另一轮环境仍在运行。

停止入口可重复双击。没有有效运行清单时，它只显示“无需停止”，不会扫描或终止其他服务。

## 精确隔离与清理

本地环境使用由当前工作树规范路径哈希派生的唯一 Compose project，并仅绑定回环地址上的专用
端口。运行清单记录 API、Web、浏览器宿主的 PID、创建时间和命令标记。停止时必须重新验证工作树、
Compose 标签和进程身份；验证不匹配的对象只报告、不终止。

启动器不按端口杀进程、不运行全局 Docker 清理，也不连接或停止 Phase 2–8 verifier、主工作树、
stash、备份或其他项目资源。
