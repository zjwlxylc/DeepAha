# Beta 邀请准入与账号管理方案（2026-09-20）

目标：支持小规模真实用户体验及反馈，管理员在网页完成发码、回收名额和账号维护，保持 SG1–SG7.2 审核/资格/推荐语义不变。

## 产品与权限
- `DEEPAHA_ALLOW_REGISTRATION=0` 全局关闭注册；开启后也必须使用有效邀请码。已有账号登录不受该开关影响。
- 管理员 `admin` 是独立权限，普通邀请码只能建立 `user`，不授予 operator/reviewer/admin。
- 邀请码随机生成（至少192 bit），数据库只存 SHA256，明文只在创建时返回一次；不放 URL/query、日志、审计或列表。
- 默认单码1人、7天；可选1–1000人、1–90天；批次备注1–120字，单次创建1–50个码。过期/用尽/撤销不可兑换；撤销不封禁已注册账号。
- 注册原子完成账号创建、名额占用和兑换记录，并记录准入说明版本；失败不消耗名额。按来源限流，数据库写锁避免超兑。
- 用户列表分页搜索，显示账号、角色、状态、创建时间、来源邀请码和批次；不暴露密码、令牌、个人画像、反馈自由文字。
- 管理员启停账号、调整角色、撤销全部会话；角色/状态变更立即失效旧会话。禁止锁死最后一个活跃管理员，禁止网页自我降权/停用。
- 人工核验身份后由管理员生成30分钟一次性密码重置码；新码撤销旧码，重置后撤销所有会话。仅线下安全交付，不自动发送邮件/消息。普通用户可用旧密码修改自己的密码。
- 账号退出/个人数据：沿用画像页已有个人导出、清除和Lab撤回功能；停用不声称物理删除或自动删除备份。账号恢复也不恢复旧会话。
- 现有机会反馈和匿名化反馈候选继续使用；邀请批次不进入资格/推荐算法，不自动同意Lab实验。
- 网页用户管理专属审计可按管理动作追溯，不记录邀请码、重置码或密码。

## 技术与迁移
新增邀请码、兑换、重置码表，不修改已有业务表字段；显式 upgrade-access 命令创建这些表。使用既有 SQLite BEGIN IMMEDIATE / PostgreSQL advisory lock 保证原子性。现有数据库需先备份再迁移，应用启动检查新增表。新安装初始化含新增表。首个admin由宿主CLI显式授予指定已有运维账号，不自动批量提升operator。

独立模块 access.py / access_api.py / access-ui.js；只在现有认证、CLI、导航添加接线。复用CSRF/Origin、cookie及口令散列机制。
