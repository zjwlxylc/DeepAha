# SG6.2 Windows 本地复现与人工验收

版本：**DeepAha 3.6.2-rc1 / SG6.2**

## 1. 升级前

1. 停止旧版 API / Worker。
2. 保留现有数据目录，不移动、不删除：
   `C:\Users\LENOVO\deepaha-data`
3. 将 3.6.2-rc1 ZIP 解压到一个**新的程序目录**；不要覆盖唯一旧源码副本。
4. 双击根目录 `启动机会星图.cmd`。

首次启动会依次执行已有升级，然后执行：

`upgrade-sg6-2`

本地 SQLite 会先生成并验证备份，再刷新可重建的 `qualification_compiler` Target 派生摘要。**不会重新调用 WMA，不会创建 VerifiedFact/Rule，不会要求字段人工审核。**

第二次启动应直接报告 SG6.2 已是当前版本，不重复写入。

## 2. 最关键的真实画像验收

登录普通用户或 owner，打开“我的 → 我的关注方向”，填写：

- 学历阶段：`专科`
- 专业：`计算机`
- 户籍地区：`浙江省宁波市`
- 优先机会类型：勾选 `事业单位`
- 关注城市：`宁波`

专业代码、毕业年份、出生日期可以先留空，以模拟此前截图中的真实使用状态。

打开“我的机会星图”。

### 预期

- 明确 Evidence 支持“本科/硕士及以上”等高于专科的硬学历要求时，SG4 应为 `INELIGIBLE`，该机会不得进入个性星图候选。
- Evidence 尚不足以正式否定、但 Candidate 条件和画像存在明显学历冲突时，正式 Eligibility 仍必须是 `UNCERTAIN`，但卡片只能标为“资格待核对/继续探索”，不得占据“今天真正值得你看的” headline Top 3。
- 如果没有任何安全 headline，**headline 为空是正确行为**，不能为了页面好看填入高风险机会。

在本次用户上传的验证快照中，300 个事业单位/招聘 Target 对上述类似画像为：

- 199 `INELIGIBLE`；
- 100 `UNCERTAIN + HIGH qualification risk`；
- 1 普通 `UNCERTAIN`。

其中 100 个主要来自扫描型 PDF：原件存在，但没有可验证、与原件哈希绑定的 OCR 派生文本，所以系统故意不硬判。

## 3. 查看“适合我吗”

选择一个明确写有学历/学位条件且 Evidence 可定位的岗位，打开“适合我吗”。

应看到：

- 总体 Eligibility；
- 已识别资格条件；
- Evidence 支持状态；
- `compiler_state` / 未解决条件；
- qualification risk（若有）；
- 原件/Excel Sheet-Row-Column 等依据。

不能看到“模型估计 92%符合”之类概率，也不能因一个未定位 Candidate Fact 直接得到 `INELIGIBLE`。

## 4. 补全更多资格画像

“更多资格信息”可选填写：

- 最高学位；
- 当前学业状态；
- 国籍；
- 政治面貌；
- 相关工作经历年限；
- 资格证书；
- 职称；
- 语言证书；
- 当前团队人数。

这些信息只在 DeepAha 本地用于确定性资格核对，不发送给 WMA。

## 5. 审核老路线防回归验收

以 reviewer/owner 打开审核收件箱和一份 WMA 返回。

**必须仍然只有：**

- `通过并收录`
- `不通过`
- 可选整体说明

**绝不能出现：**

- “确认学历字段”
- “确认专业字段”
- “确认年龄字段”
- 单岗位逐字段批准
- 事实晋升按钮
- 规则批准 / scope approval

SG6.2 的 compiler 是后台确定性派生能力，不是新的人工审核流程。

## 6. 数据安全检查

升级前备份位于数据目录的 `backups` 下。

SG6.2 不应改变：

- WMA 原始 ZIP / HTML / PDF / DOCX / XLSX；
- Opportunity / Unit；
- Overview Decision / Publication；
- Result Snapshot / Task；
- 用户账号/既有画像字段。

只会补充 CatalogTarget 的可重建资格 compiler 摘要和新的可选画像字段值。

## 7. 人工验收重点

请重点判断：

1. 你原来截图中“专科却被硕士/本科岗位作为优先推荐”的问题是否消失；
2. `UNCERTAIN` 是否变成“有明确原因的不确定”，而不是所有机会一律模糊；
3. 已有可靠 Evidence 的硬条件能否真正进入计算；
4. 扫描 PDF / 相关专业 / 例外条件是否仍然谨慎保持不确定；
5. 审核员是否仍然只做一次整体决定，没有回到旧逐字段审核路线。

满足以上条件后，才建议人工接受 SG6.2。
