# SG2 本地验收入口

版本：**3.2.0-rc1 / SG2 多类型 Opportunity Core**

前置条件：SG1 已由用户人工验收通过。本版不改变 SG1 的“父公告一次审核、具体行动目标进入总览”原则，只把这一模型从招聘岗位推广到竞赛、科研、奖学金、人才政策/补贴、升学/夏令营和成长实践等机会类型。

## 你本地先看什么

### 1. 你的真实 WMA 招聘数据

继续使用原目录：

`C:\Users\LENOVO\deepaha-data`

本版**没有 SG2 数据库迁移**。如果该目录已经通过 SG1 升级，直接启动 3.2.0-rc1 即可；106 个具体岗位应保持不变。

### 2. 体验 SG2 新增的多类型能力

SG2 不用伪造你的真实数据库。仓库内提供 6 个明确标记为虚构的体验包：

- 招聘：2 个岗位；
- 竞赛：2 个赛道；
- 政策：1 个政策分项；
- 科研：2 个研究方向；
- 奖学金：2 个资助档次；
- 升学：2 个项目类别。

在一个**单独测试数据目录**中运行：

```bat
set DEEPAHA_DATA_DIR=C:\Users\LENOVO\deepaha-data-sg2-test
py -3.13 -m deepaha.product.cli init
py -3.13 -m deepaha.product.cli user-add owner --roles user,reviewer,operator
py -3.13 -m deepaha.product.cli examples --actor owner
```

然后启动：

```bat
set DEEPAHA_DATA_DIR=C:\Users\LENOVO\deepaha-data-sg2-test
py -3.13 scripts\launch_product.py --install
```

进入审核收件箱，对这 6 份**虚构体验包**逐份整体通过。再打开“机会总览”，重点检查：

- 竞赛显示“赛道”，不是“岗位”；
- 科研显示“研究方向”；
- 奖学金显示“资助档次”；
- 人才政策的“滚动受理”不会被伪造成某个固定截止日期；
- 升学/暑期项目显示“项目类别”；
- 没有在线申请 URL 的政策仍然可以进入总览；
- 陌生字段仍可在详情和文本搜索中找到。

## SG2 人工验收建议

建议至少完成下面 8 项：

1. 原真实招聘数据库仍为 106 个具体岗位；
2. 竞赛两个赛道分别进入总览；
3. 竞赛详情出现“赛道内容 / 赛事共同规则 / 所属赛事”；
4. 科研实验室只做 scope，研究方向才是行动卡；
5. 奖学金两个档次分别进入总览，陌生“综合素质说明”可搜索；
6. 滚动政策没有假截止日，线下办理不因缺 URL 消失；
7. 升学项目两个类别分别进入总览；
8. 手机宽度下无横向溢出，收藏仍绑定具体行动目标。

人工确认 SG2 通过前，不进入 SG3。
