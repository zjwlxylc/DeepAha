# DeepAha 来源资产导入工具 v0.2.0

**在 v0.1.0 上增补“程序调用 Codex CLI，从资料库取回文件”。本版是未测试的源码增量包，不是免安装 EXE，也不是已接通用户资料库/生产系统的发布包。**

## 这次增加什么

原来：你先手动下载，再选文件导入。

新增入口：**双击工具 → 从资料库获取 → 程序后台调用 Codex 列出资产包 → 选中并取回 → 原有预览 → 你确认后导入。**

不是让你另外打开 Codex 输入指令，也不是让 Codex 自己决定入库。Codex 只负责通过已经具备权限的文件工具定位、导出原件；校验、去重、提交和回执仍由原程序处理。

## 必须明确的实际前提

本机需要 Python 3.11+（窗口需 Tk）、已安装并登录的 Codex CLI。**被调用的 Codex 必须实际拥有 ChatGPT 个人资料库“DeepAha网络资源”的读取与原件导出工具。**同一账号登录、MCP 框架可用或本工具已安装，都不单独证明有这个权限。

代码会调用 Codex 尝试列出和取回文件；没有相应工具、未授权、只提供摘要不能导出原件时，会明确提示并停止。不会假装成功，不会用本地同名目录或其他网盘替代，不会让模型重写一份 JSON 冒充原件。

**本轮没有运行测试，没有启动实际 Codex，没有验证你的账号权限，也没有连接 DeepAha。**当前账户与工具接入仍需在你的实际环境确认。资料库能力与 DeepAha 服务器导入接入是两件独立的事。

## 你的使用步骤

1. 将本版 ZIP 解压到新目录，保留整个目录结构。双击 `启动来源导入.cmd`（英文入口 `launch_windows.cmd`）。
2. 点主窗口 **“从资料库获取”**。Codex 程序路径默认为 `codex`，需要时选择实际安装路径；配置名称/模型可以留空，沿用本机 Codex 配置。
3. 点 **“1. 读取资料库”**，程序在后台运行 Codex，不打开对话终端。只读取个人资料库 `/DeepAha网络资源` 的 Handoff 资产包列表。
4. 选中一个批次，点 **“2. 取回选中文件并载入”**。程序取得原始 JSON 与其必需附件，检查实际文件、大小、哈希及导入契约后，回到主窗口载入。
5. 原有操作不变：点击 **“预览（不入库）”**，核对目标环境与变更；你再次确认后才提交。

“本地演练”仍然默认开启，防止误写正式系统。正式使用前须完成原 v0.1.0 的服务端接入，再取消演练并配置实际服务器。**取得真实文件不会自动把演练改成生产。**

资料库调用可能消耗 Codex 使用额度。默认不允许模型生成的 Shell 联网；只有实际导出方式需要下载地址时，才在窗口勾选“允许下载原件时使用网络命令”。这不改变资料库的读取权限，不能用它解决没有资料库工具的问题。

## 保持不变

- 手动“选择本地文件”仍保留，但仅是独立的兼容入口，不是自动获取失败后的隐式替代。
- 获取后不会自动提交数据库、批准来源、启用 WMA 或上传回执。
- 原有导入 API、仓储、事务、权限、去重和回执协议不变。
- 原有测试文件、样本及 v0.1.0 历史证据随包保留，**不是本版通过测试的证据**。
- 不自动安装插件，不抓取 Cookie，不猜 ChatGPT 私有下载接口，不提供资料库全量同步。

## 文件位置

默认数据目录沿用原版：Windows 为 `%LOCALAPPDATA%\DeepAhaSourceImporter`，其他平台为 `~/.deepaha-source-importer`。

| 子项 | 用途 |
|---|---|
| `codex-library.settings.json` | 本机获取设置，不含密钥，与原 `settings.json` 独立 |
| `library_downloads/pull-.../` | 已取回并通过导入格式校验的原件及依赖 |
| `library_runs/` | 目录清单与下载来源记录；**不是数据库导入回执** |
| `receipts/` | 原有导入回执 |

不必迁移已有本机配置/回执，解压到新程序目录即可继续使用原数据目录。不得把下载来源记录当成“DeepAha 已接收”。

## 源码位置

新增 `deepaha_importer/codex_process.py`（进程与设置）、`library_pull.py`（列表/取回协议及校验）、`library_window.py`（中文获取窗口）。原 `gui.py` 增加入口，`cli.py` 增加 `library-list` / `library-fetch`。

原 `ImportService`、`Package`、事务、认证和服务器路由继续复用，没有另建数据库或正式 Source Registry。

先读 `docs/CODEX_HANDOFF.md` 的 v0.2.0 增量段，以及 `docs/LIBRARY_PULL.md`。后者记录实际调用参数、配置边界、工具证据要求与尚未验证项。

新版本状态以 `docs/IMPLEMENTATION_STATUS.md` 和 `evidence/RELEASE_STATUS_v0.2.0.json` 为准；`evidence/final_verification.*` 原样保留，属于 v0.1.0 历史记录。
