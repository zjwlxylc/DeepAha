# 来源资产工作台 v0.3.0 · 产品与技术设计

## 目标与授权
本轮用户已授权：选择受控 State 基线，审核30轮 Handoff，与 WB-scout 比较，规划真实反馈，并在原 v0.2.0 上完成升级和交付。只处理用户提供的原件，不访问生产数据库、不批准正式来源、不启动 WMA。界面和报告把研究判断、程序检查、人工决定、系统回执分开。

## 方案取舍
不选择推倒重写：v0.2.0 的严格 Package、ImportService、事务、权限、回执及 Codex 进程桥保留。不选择仅加一个“批量导入”按钮：两种实际资产均存在结构漂移，直接送入旧接口会失败。选择增加独立的研究包适配层和本地审核工作台；旧单批提交界面继续可用，新的批量交接契约等待主系统受控接入。

## 工作流程
1. 用户选择一个或多个 JSON/ZIP/文件夹；文件名不用于决定业务真实性，生产者命名空间可明确指定。
2. 离线检查：原字节哈希、ZIP安全、JSON、批次身份、候选和Brief版本、引用、附件及分数算术。不联网、不执行附件、不补造字段。
3. 先按同一生产者+候选键归并历史版本。URL完全相同只提示“相同入口”，同域不同栏目只建立关系建议，不能自动合并机构。保留每一版本、证据与原文件定位。
4. 操作者只处理疑点，可保存“接收至候选暂存的建议 / 暂缓 / 不采用”；阻断问题不能标为可交接，修改后使旧导出结果失效。每次决定有操作者、原因、时间，撤销也留记录。
5. 导出研究交接包，含原件、规范审查、决定与SHA清单；不是正式导入回执。原兼容窗口仍处理旧执行契约的预览/人工提交/回执。
6. 系统反馈从 DeepAha 取得；仅载入JSON不能证明来源真实性。格式核验、实例与包哈希核验、原系统查询或签名验证分开显示。

## 架构
`research/ingest.py` 安全原件读取；`research/normalize.py` 确定性字段转换；`research/audit.py` 版本/引用/附件/重复审核；`research/baseline.py` 状态链与受控基线；`research/workspace.py` 持久化本地审核及导出；`workbench.py` 回环HTTP；`web/` 原生浏览器界面。Python 3.11+，核心无新第三方运行依赖。

工作台只绑定127.0.0.1，随机会话令牌、Host/Origin校验、只接收有界请求、不提供任意路径读写、不渲染原始HTML；外链只允许公开HTTP(S)，不自动访问。数据保存在独立 research_workbench 子目录，与原演练库/回执隔离。

## State 基线
选择X30但保持原件不变。新文件保留原状态字段，新增受控基线标识、原件SHA、明确范围、永久迁移缺口及后续继承政策。历史完整性仍为PARTIAL；从本基线开始可单独证明连续性。无系统导出不能宣称全局去重。来源旧首次发现时间不因复查而重置。

## 人机交互
默认“选择研究包”而不是填写JSON/URI/数据库配置。顶部说明当前步骤和下一动作；主体使用来源名称、机构、入口、问题和处理意见；JSON、哈希、英文状态码放在可展开详情。暖白底、深蓝主动作、少量橙色提醒；颜色不单独编码状态；桌面双栏，窄屏单栏；可键盘操作，表格不让整页横向滚动。

## 范围与非目标
实现本地审核与交接，不伪造主系统已接收。真实账号、正式Source批准、WMA调用、生产存储、回执签名端实现不在本工具擅自完成。v0.2.0程序调用Codex获取资料库的入口保留，仍需本机有真实工具权限；手动上传为一等入口。
