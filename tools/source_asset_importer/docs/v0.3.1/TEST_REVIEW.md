# v0.3.0 实机测试包核验与 v0.3.1 修正

## 结论

本次本地审核与导出主要结果符合预期，原件、候选分组和审核意见之间的关系能够核验。它仍然只是外部研究资产交接，不证明DeepAha已接收、来源已批准或WMA已启动。“从资料库获取”在用户实测中未完成，旧版交互与诊断不合格；本版修复能够本地控制的问题，但尚不能宣告用户账号的资料库直连成功。

核验输入为 `DeepAha_Research_99762cfa35a48bfe_r58.zip` 和用户截图；另外只读对照v0.3.0源码、此前用户提供的DeepAha-main.zip。没有读取用户电脑上的Codex日志，没有写入主项目或生产数据库。

## 2. 不能因为“审核已完成”而忽略的事项

48项建议接收中，23项仍有非阻断问题，但都保存了“已知晓疑点”。这符合研究暂存阶段的容错，不符合“全部已核实、可自动采集”的解释。39条问题事件包含评分算术8、引用文本规范化7、多个入口7、历史入口变化5、无有效入口4、入口格式3、附件大小声明3、首次发现时间2。同一问题事件不一定代表一个不同文件；附件大小3条涉及2份实际原件。

本地操作者字符串不是DeepAha服务端认证身份。即使某条原因写着“批准采集测试1”，其结构化决定仍为PROPOSE_STAGING，authority仍是LOCAL_REVIEW_ONLY_NOT_SYSTEM_APPROVAL，不授予来源启用权。

FeedbackDeclarations为空；submission_status为NOT_SUBMITTED；delivery_mode为MANUAL_EXPORT_ONLY；各候选system_source_id和collection_enabled均为null。导出结构没有将本地建议伪装成真实系统反馈。

## 3. 与DeepAha结构的关系

按照本次可用代码快照，正确关系仍是：

外部Scout研究 → 本地审核/去重与原件交接 → DeepAha候选暂存与回执 → 正式来源/入口批准 → 有范围的公告发现 → 显式Direct WMA调查 → 原件与候选事实回收 → 核验/发布。

本工具占据前两步，Codex只是资料搬运助手，不是正式机会生产智能体。本包integration_status明确要求独立R2暂存适配，不能提交旧单批v1导入接口，也不能把52个来源首页直接当52个WMA调查任务。

主仓对照基于ZIP comment `d0918ec1245264e271f42a18d54c0fb903000c00`。该快照尚无scout_intake模块；已有来源策略与调查登记链应复用。没有检查用户后来是否在另一分支完成了R2，没有验证生产部署，故不把快照缺口说成当前线上必然缺口。

## 4. 导出时间字段缺陷

旧交接created_at为2026-09-13 01:28:53 UTC，等于Audit.analyzed_at；最后审核为06:25:04 UTC。这不是能够信任的交接包生成时间。源码确认是导出时复用了检查时间，不是本次推断用户电脑时钟出错。

v0.3.1首次新导出分别写入检查时间、最后审核时间和真实导出时间。相同版本重复下载复用历史字节，旧v0.3.0包不改写。对本次r58旧包做了隔离迁移回放，重取字节与原包一致；新导出测试保留全部旧意见，同时产生正确的时间关系。没有伪造另一份替换用户原件。

## 5. 资料库获取失败：已确认与未确认

截图表明资料库请求处于等待，没有成功文件清单。源码证实：旧版缺前置CLI能力检查；取消按钮位于模态对话框外；客户端无整体轮询上限；诊断不足。弹窗打开时其余页面通常不能交互，取消按钮即便看得见也不能正常使用，解释了明显的交互障碍。

但用户包不含该次Codex终端事件或错误。不能断言此次具体是缺少CLI、网络、模型、授权或哪个参数。旧代码对“本机已经配置好资料库工具”的依赖没有可靠地在界面前置说明与验证；这是设计应承担的问题，不应归咎于用户不会操作。

OpenAI公开文档支持Codex exec、结构化输出、MCP/Apps等扩展机制，也明确提供ChatGPT资料库页面下载功能；没有从这些资料得到“同一账号本地Codex必然拥有完整个人Library API”的依据。文档还区分沙盒命令网络与Apps/MCP工具通道，因此勾联网不会产生账号权限。此结论是能力边界，不是宣称所有账号永远无法直连。具体来源见CHANGE_DESIGN.md。

## 6. 本次修正

保留由工具调用Codex及原手工路径。新增只读本机检查，随后才发起真实目录请求；分别显示程序是否正常、目录是否读到、原件是否取回。取消、阶段、计时、诊断下载移进弹窗；按按钮重复点击不能反复创建前端任务；错误和取消后恢复操作。目录阶段最多60秒，单文件按设置，整批最多10分钟；不无限搜寻缺失能力。

高级配置折叠；联网开关说明限制；从同一弹窗可以选择已下载文件或整个文件夹。已完成审核不再以空列表暗示“文件没有了”，而是给出查看已处理和继续导出的动作。

安全诊断只保存允许的元数据及错误类别，不保存Cookie、密钥、邮箱、原始stdout/stderr、文件正文或模型推理内容。无真实工具证据或原件字节校验不通过时，仍然不能报成功。没有解除沙盒、自动安装插件、猜私有接口或启动生产采集。

## 7. 复验与剩余边界

用户原包在v0.3.1重新分析后，summary、来源对象、身份键和问题列表与旧Audit一致。真实本机“没有Codex”路径正确快速返回CODEX_NOT_FOUND；进程取消、登录分类、参数检查、额度错误分类使用受控合成CLI测试，不代表用户云端账号。

浏览器正常访问回环地址被本环境管理员策略阻止，已如实记录，未绕过。另行进行了离线DOM交互测试（显式替换fetch/下载/存储）和独立真实回环HTTP权限测试；两者都不是完整浏览器HTTP端到端验收。离线DOM检查包括r58恢复、52项已处理展示、弹窗内取消可达、失败诊断、390像素无横向溢出及原手工选择仍可用。

Windows实机、用户Codex账号的目录及原件能力、DeepAha R2接收、WMA生产与真实系统回执均未在本轮验证。**修正版可以交付测试，但不能把“本地错误处理已修复”升级成“资料库实连已跑通”。**
