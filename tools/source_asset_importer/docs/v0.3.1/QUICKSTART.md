# v0.3.1：升级与资料库获取

先退出旧版本，再把新ZIP解压到新目录，运行 `启动来源导入.cmd`。这是源码包，不是免安装EXE；仍需Python 3.11及以上。不要删除旧程序或本地数据目录。

## 继续已有审核

同一Windows用户、同一默认数据目录下，程序继续读取 `%LOCALAPPDATA%\DeepAhaSourceImporter\research_workbench`。你本次52个来源、58次操作不会因为更换程序文件夹而被重新初始化。自定义过数据目录的，仍需指定同一个目录。跨电脑迁移先关闭旧程序再备份完整数据根目录，不能只把交接ZIP当作本地会话数据库。

原先“待我处理”为空，现在显示“本次来源都已处理”。点击“查看已处理来源”即可看到已保存的52项意见；“前往导出交接包”继续下一步。这里的“需先补充4项”仍保留，不会因暂缓而消失。

## 文件已经下载

点“从资料库获取”，在弹窗上方选“选择已下载文件”或“选择本地文件夹”。可选择整个WB-scout.zip，也可一次选择多份GPT Handoff。此路径不启动Codex、不消耗模型额度。它保留原来的手工方式，不要求在终端给Codex发任务。

ChatGPT资料库页面可选一个或多个文件后点击下载，再回工具选择原件。工具不会操作登录Cookie或调用未公开的资料库接口。

## 尝试资料库直连

在弹窗选择目录，点“检查连接并读取目录”。程序自动调用本机Codex，不要求你自己复制执行提示词。

先检查程序、参数支持、登录状态与Apps开关（这些是本机元数据检查，不调用模型）；只有通过后才启动一次真实目录请求。高级设置里的“本机配置名称”是你本机Codex实际存在的配置，不是ChatGPT项目名；留空使用本机默认配置。来自另外一个受信任项目目录的项目级配置不保证会被本工具的隔离临时目录继承。

目录成功只证明取得文件清单。选中文件后才会另行请求原始字节，核对文件ID、版本、大小和SHA-256；原件失败不会用模型摘要伪造文件。

资料库直连并非所有Codex账号都已获支持。登录同一个ChatGPT账号，不等于该次本地CLI运行已经取得个人资料库读取与原件导出工具；增加提示词、选择更强模型或勾联网不能创造这项权限。本版没有提供能够通用于所有账号的资料库API，也没有验证你本机的实连成功。

## 进度与取消

进度、已等待时间和“取消本次获取”现在都位于弹窗内部。取消会通知后端停止本轮Codex进程；已保存审核保持不变。目录阶段上限60秒，前置元数据检查每项8秒；原件单文件遵循设置，整批最多10分钟。重复点击不能启动重叠的前端请求。

“允许原件下载阶段使用联网命令”只影响下载阶段的沙盒命令，不代表额外授权连接器或放开账号权限。它默认关闭，已有明确保存的选择不会被版本更新悄悄重置。

## 连接失败以后

弹窗保留明确结果及“下载本次连接诊断”。诊断记录错误代码、CLI版本、登录方式分类、参数检查、阶段、退出码、时长和有限事件类型。不记录密码、Cookie、账号邮箱、文件正文、原始终端输出或模型思考内容。Codex自身的账户/运行记录由Codex管理，不由这个工具的诊断文件代替。

- `CODEX_NOT_FOUND`：本机未找到CLI程序；核对安装或在高级设置指定实际程序。
- `CODEX_FLAGS_UNSUPPORTED`：缺少必要执行参数；不绕过沙盒。
- `CODEX_AUTH_REQUIRED`：需在Codex自身完成登录。
- `LIBRARY_UNAVAILABLE` / `LIBRARY_AUTH_REQUIRED`：本次会话无可用个人资料库工具或授权。
- `LIBRARY_NO_TOOL_EVIDENCE`：缺少本工具可核验的成功调用记录，不直接断言平台永久不支持。
- `LIBRARY_EXPORT_UNAVAILABLE`：能看到目录但无法取得原件。
- `CODEX_TIMEOUT`：达到上限，已停止；诊断留存，不能解释为资料库为空。

不要把密钥粘进原因或配置框。需要定位本机故障时，只提交新生成的诊断JSON即可。

## 导出时间及主系统接收

新生成交接包分开保存 `analyzed_at`、`last_reviewed_at` 和 `exported_at`，`created_at` 指首次真实导出时间。同一审核版本重复下载会复用原包，不更新时间、不改哈希。已有v0.3.0包也原样保留，其旧时间缺陷在分析报告中说明，不做无声改写。

本地建议接收仍不是DeepAha批准来源。研究交接ZIP需要主项目的R2候选暂存适配器，不能直接提交旧单批v1接口或传给WMA启动采集。
