# DeepAha Source Asset Importer Implementation Plan

**Goal:** 实现已批准的 Handoff → 预览 → 人工确认 → 受控入库 → 回执流程，交付完整源码供 Codex 在真实仓库接入。

**Architecture:** 一个确定性导入服务，共享给本地 CLI / 中文 Tk 窗口 / HTTP 路由。本地 SQLite 仅用于明确标记的演练；提供 PostgreSQL 研究暂存仓储与 FastAPI 路由适配，但不假装这些就是主项目已有表/权限接口。正式来源审批必须通过宿主回调，不把入库当批准。

**Tech Stack:** Python 3.11+；客户端、核心和演练仅标准库；PostgreSQL 可选 psycopg3；FastAPI 可选。

**Spec:** `docs/baseline/DeepAha_Scout_新版使用与导入方案_v1.0.md` 与配套 Scout v2.2.1 Prompt，及本对话确认的本地启动入口、回执回传可选。

## Global Constraints
- 不修改用户主仓、数据库、定时任务；不联网采源、调用模型或自动同步资料库。
- schema_version 保持 deepaha.source-intelligence.run.v2.2；提示词版本不是数据库版本。
- 外部 revision/base_revision 与系统版本分开；不得猜缺失字段、凭据、实际 Source ID。
- 预览不写业务数据；确认绑定包字节、依赖、身份、目标、动作、数据版本与时效。
- 同批同字节幂等；同批不同内容拒绝；来源级去重、整批事务、回执回读。
- 演练不能报告正式入库/真实 WMA 启用；正式默认不开启；回执不自动上传。

## Execution units
1. 写测试，验证严格 JSON、Handoff 字段/引用/附件路径及哈希，执行 RED；实现 `contract.py` 和不可变交付包。
2. 写仓储/服务测试，验证只读预览、确认令牌、幂等、版本冲突、事务回滚、权限、原件及回执，执行 RED；实现 `repository.py`, `security.py`, `service.py`。
3. 写 HTTP/客户端测试，验证认证、限制、无重定向、读回回执及失败恢复，执行 RED；实现 `http_api.py`, `client.py`, 可选 `fastapi_adapter.py`。
4. 写 CLI 和窗口状态测试，执行 RED；实现中文窗口/CLI、双击入口、配置与演练。真实 Windows 原生外观留人工验收，不宣称已测。
5. 执行全套本地测试、离线 CLI 与真实 loopback HTTP smoke、语法与打包回读；输出真实验证记录、接入说明、源码 ZIP。

每个单元完成后检查与基线一致；不把仍待实环境核验的事项写为 PASS。
