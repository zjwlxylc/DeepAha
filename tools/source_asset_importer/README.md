# DeepAha 来源资产工作台 v0.3.1

**把研究包整理成可审核、可追溯的资产，再交给 DeepAha。**

这是 v0.3.0 的修正版：增加资料库连接检查、可取消进度、有限等待与诊断导出，修正审核完成提示和导出时间；不重写原导入内核。

**资料库直连仍是条件能力，不是已在所有账号验证的功能。** 没有真实个人资料库工具时会明确停止；本机程序不能凭同一ChatGPT账号创造这个权限。

当前新版完成的是**本地批量检查、审核记录和交接包导出**。当前48份真实Handoff原样都不符合旧严格执行契约；本版不通过删字段或放宽权限强行导入。新交接包需要DeepAha的R2候选暂存适配器。未连接生产库、未启用来源、未启动WMA。

## 开始使用

需要本机安装 **Python 3.11或更高版本**，以及正常可用的桌面浏览器。新版核心不需要额外pip依赖。不是免安装EXE；Windows实机与用户账号的Codex取回权限尚未在本轮验证。

1. ZIP解压到**新的文件夹**，保留目录结构，不覆盖旧v0.3.0或v0.2.0程序。
2. Windows双击 **`启动来源导入.cmd`**。程序启动本机服务并打开浏览器。首次使用界面为空；同一台电脑使用默认数据目录时，会恢复已有本地审核，不预先连接生产库。macOS/Linux在解压目录执行 `python3 run_importer.py`。
3. 点 **“选择文件”**，可同时选择多份GPT Handoff和WB-scout.zip，也可选择整个研究文件夹。输入只在本机处理。State用作历史/引用上下文，不重复增加候选。
4. 点 **“开始检查”**。界面按来源身份分组展示，先看有疑点的对象。单击名称后查看“处理意见、依据与附件、版本记录”。哈希和原始JSON放在详细信息，不要求你填写。
5. 填操作者和原因，保存 **“建议接收为候选 / 暂缓 / 不采用”**。主入口有多个时需要选择；有疑点需要明确核对；已保存意见可撤销，历史记录不会丢。
6. 进入 **“导出交接包”**。包内带全部原件、审核表、版本、意见和SHA清单。没审核完也可导出备份，但会标“未完成”，不会冒充批准结果。
7. 只有DeepAha接收后返回真实系统反馈，才读取到第4步。工作台检查格式和包绑定，不把JSON自称PRODUCTION当成真实系统认证。

**继续昨天的审核：**启动后，左侧“最近的本地审核”打开原会话。审核会自动持久保存，关闭页面不会清空已经保存的意见。

## 从资料库获取：由工具调用Codex，不要求你输入命令

点右上角 **“从资料库获取”**，选择 `/DeepAha网络资源`、`/deepaha` 或 `/DeepAha机会星图`，点击“检查连接并读取目录”。先检查Codex程序、参数支持、登录状态和Apps开关，随后才请求真实目录。清单成功不等于原件下载成功；选中后另做字节核验。高级设置可配置本机程序路径、配置名、模型和原件超时。

检查或取回过程中，弹窗内可以查看阶段、等待秒数并点击“取消本次获取”。失败后点击“下载本次连接诊断”。元数据检查每项8秒，目录请求最多60秒，单文件按配置、整批最多10分钟；不无限轮询。

文件已下载时，在同一弹窗选择“选择已下载文件”或“选择本地文件夹”，不需要Codex。

需要本机已安装/登录Codex，并且该Codex会话**确实具备个人Library文件读取和原件导出能力**。同一账号、安装了Codex或有普通文件工具都不代表自动获得此权限。本轮只验证进程协议和文件边界，未验证用户账号实连。缺工具/权限/原件时明确报错，不用模型摘要重造JSON；手动选择原件始终可用，不是被取消的备用方案。

资料库取回可能消耗Codex额度。联网下载命令默认关闭；勾选不会创造Library权限，也不改变候选/生产边界。获取后不自动提交，不自动上传回执。

## 这版解决什么

- 多文件/一层ZIP/文件夹输入，GPT与WB差异字段适配。
- 同候选多版本归并展示；相同URL提示关系，不强行合并机构。
- 附件SHA/大小/目录别名核对；原件与声明并列，缺项不猜。
- 评分算术、来源入口、跨批证据和时间异常显式提示。
- 本地审核可保存、撤销，多个窗口用版本号防止互相覆盖。
- 导出带原件与完整版本，不只生成“最新网址表”。
- 系统接收、来源批准、实际运行三层反馈分开。
- 桌面左右双栏，手机宽度列表/详情切换；中文动作、键盘标签、触控按钮。

## 本地数据在哪里

沿用原数据根目录：Windows `%LOCALAPPDATA%\DeepAhaSourceImporter`；其他平台 `~/.deepaha-source-importer`。

| 子目录/文件 | 内容 |
|---|---|
| `research_workbench/review.sqlite3` | 新版本地审核会话、意见、撤销与版本记录 |
| `research_workbench/blobs/` | 内容寻址原件，不要手动编辑 |
| `research_workbench/exports/` | 审核交接ZIP |
| `library_diagnostics/` | 脱敏连接诊断，不含原始stdout、邮件、正文、密钥或思考内容 |
| `codex-library.settings.json` | 不含密钥的Codex调用设置 |
| `library_research_downloads/`等 | 资料库取回原件与过程证据，具体见取回结果路径 |
| 原 `receipts/` | 旧内核回执，研究导出不写成真实导入回执 |

备份整个数据根目录前先退出程序。共享交接ZIP时注意包含你选择的完整原件和本地操作者记录，只交给有权访问这些资料的人。

## 兼容旧功能

需要旧严格契约的单批演练/预览/提交时，点击左侧 **“原单批兼容窗口”**，或双击 `启动单批兼容窗口.cmd`。它需要Tk组件。旧界面仍默认演练；只有服务端集成、环境、权限都确认后才能按旧流程显式提交。

旧CLI原样保留。新CLI：
```bash
python -m deepaha_importer workbench --no-browser
python -m deepaha_importer research-audit /path/to/WB-scout.zip /path/to/Handoff.json --output /path/to/audit.json
```
旧v0.2说明完整保存在 `docs/v0.3.0/README_v0.2.0_HISTORICAL.md`。两份旧包和历史证据不被本版覆盖。

## 校验与交付边界

读取 `docs/v0.3.1/VALIDATION.md` 查看本次测试的实测结果与局限，**不要用旧evidence中的v0.1/v0.2状态判断本版**。本版测试包含旧内核回归、新版安全和本地交互；真实Windows、实际Codex账号、主系统生产接入与发行方反馈认证未验证。

当前环境浏览器被管理员禁止URL导航，因此浏览器截图/交互测试使用离线DOM与真实本地应用方法，fetch/download/storage有明确测试替身；HTTP令牌/Origin/Host等另以实际回环服务器测试。不能称完整浏览器HTTP端到端或Windows验收。
