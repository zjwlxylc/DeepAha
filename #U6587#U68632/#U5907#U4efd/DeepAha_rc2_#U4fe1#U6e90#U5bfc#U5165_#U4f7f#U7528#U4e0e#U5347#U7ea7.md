# 使用与升级

## 1. 现有外部工具不用重做

继续使用来源资产工作台v0.3.1。原来的手工选文件、批量研究、导出、反馈读取以及条件性的Codex/资料库功能均保留。完整系统包内 `tools/source_asset_importer/` 是本次对接的原工具源码副本，版本号仍为0.3.1，不代表小工具被升级到新版本。

## 2. 日常操作

**导出研究包 → 登录主系统 → 来源资产 → 上传 → 查看候选与备注 → 接收所选候选。**

用工具导出的 `DeepAha_Research_…zip` 原包即可，不要自行拆掉Manifest和originals，也不必把网址从报告逐条复制。页面支持拖放和文件选择。原始Handoff或WB研究ZIP也可以直接提交到同一入口，但没有工具完整意见时，不能称为外部审核已经完成。

接收后，可以搜索、分页、查看全部历史观察和Brief。需要正式用于采集的候选，在其详情里一次明确来源名称、主入口、角色、选用建议及原因，并批准为来源。不要求逐字段认证或逐条批准研究依据。

默认不允许新调查，也不安排周期采集。来源批准表单可明确勾选“允许创建新的调查任务”，但这个选项仍不马上执行WMA；新调查继续由已有“新建调查”入口明确发起。更新已有来源配置也不会保留未明确授权的新周期：本次批准后周期为关闭，需要时在来源管理重新设置。

WMA返回后进入原来的整体审核，来源研究接收不等于机会审核通过。

## 3. 回执交回工具

在研究批次页面点击 **下载系统反馈**，回到工具原审核会话读取该JSON。首次导出时保持该会话/导出历史，工具才能对上bundle_id。

在DeepAha后来批准来源、暂停来源或完成调查后，可再次下载新的反馈。事件本身保持稳定ID。工具所提示的“发行方未认证”说明这是离线文件，不应通过改文字把它假装成可信签名。

需要外部Scout继续研究时，将回执/反馈作为下一轮人工交接材料；本版不自动连接ChatGPT资料库，也不把“在资料库保存成功”说成“已经导入DeepAha”。不要给外部Scout数据库密码或WMA凭据。

## 4. rc1升级到rc2

**先停止rc1的API和Worker。完整解压rc2到新代码目录，保留原数据目录，不直接覆盖有未提交修改的仓库。**

本轮数据升级只新增来源资产表，继续使用rc1账号、Source、总览与原件。没有修改历史Alembic迁移；没有自动把旧研究/旧审核升级成来源批准。

### Windows本地SQLite

仍准备Python3.13。将 `DEEPAHA_DATA_DIR` 指向现有的重建版数据目录，再双击 `启动机会星图.cmd`。启动器发现新增表尚不存在时，先生成并校验SQLite/原件备份，再加表；不创建新的默认管理员。

显式命令更方便审查：
```powershell
$env:PYTHONPATH = "$PWD\backend\src"
$env:DEEPAHA_DATA_DIR = 'D:\DeepAhaData-rebuild'
.\.venv-product\Scripts\python.exe -m deepaha.product.cli upgrade
```
虚拟环境需先按根README安装；上述路径是用户选择的重建版目录，不是旧系统真人库。命令输出备份位置。重复升级显示already_current，不重复创建备份或记录。

### Linux本地SQLite

```bash
export PYTHONPATH="$PWD/backend/src"
export DEEPAHA_DATA_DIR="$HOME/deepaha-data-rebuild"
.venv-product/bin/python -m deepaha.product.cli upgrade
```
升级前备份在数据目录backups下；回退需要原代码及升级前备份。不能简单删表回退。恢复使用原有 `restore-backup` 命令恢复到一个不存在的新目录，避免覆盖当前数据。

### PostgreSQL

本轮没有操作真实PostgreSQL。先停API/Worker，用宿主的pg_dump与原件卷做备份并验证恢复，再在指向正确数据库的受控部署环境执行原有 `python -m deepaha.product.cli init`，创建缺失的来源资产表。SQLite自动upgrade命令会拒绝替PostgreSQL假装备份成功。

上线前检查真实权限、数据库结构、索引、对象存储、并发、代理上传上限和恢复过程。本轮SQLAlchemy定义可支持该路径，但不能据SQLite测试宣称PostgreSQL已验收。

## 5. WMA资料更新与恢复

任务创建时固定来源政策和Brief。未发送的任务遇到来源政策变化，不擅自切到新Brief：任务页显示来源配置已变化，由操作者重新创建调查。已发出的运行继续用原任务快照；恢复只按原路径回收已有结果，不为了补回执而重新发Prompt。

## 6. 常见情况

| 页面提示 | 处理 |
|---|---|
| 文件有误 | 原件保留；下载核对清单/版本/损坏项，修好后重新导出 |
| 同一研究批次内容冲突 | 使用正确run_key的新修订，不覆盖原批次 |
| 入口或身份待明确 | 保留为研究资料，在工具补齐原件后另交新版本；其他候选不受牵连 |
| 已有来源 | 明确关联已有Source，不按名称自动创建第二份 |
| 预览/政策已有变化 | 刷新当前页面核对变化后提交；不重跑调查 |
| 不知道提交是否成功 | 打开原批次看持久回执，不先重新审核 |
| 旧v1兼容窗口不通 | 当前主路径是v0.3.1导出ZIP→主系统来源资产上传；旧单批HTTP协议未接入 |

## 7. 功能样本

`examples/source-intelligence/` 含原工具实际导出的虚构交接样本与原始Handoff。可检验页面及保存流程，但不是官方来源，不能据其宣布产品真实采集效果。新安装不会自动导入或批准样本。
